## Intent

**Problem:** The gate-7 re-check 7-20 (2026-11-18) kept md-list at FAIL with finding s7-20-02 (DEFECTS.md, open, gate 4). The product is clean in the reviewer's runs: 10 of 10 valid full runs of `NativeListStatesIntegration` pass on macOS, the drag-reorder subset passes 20 of 20, and the half-crossing of the state layer is at median -3.1 ms and worst 11.4 ms against Chrome (job 007), inside one frame. The finding is in the test: `Tests/NativeListStatesIntegration.swift` lines 554 to 557 add a second tier (a Chrome envelope window of -50/+56 ms) whose misses are written as `input-latency` known gaps and not as failures. No other states suite (checkbox, switch, radio) has this tier. With it a state layer that starts 33 ms late passes 3 of 3 runs and one that starts 50 ms late fails 3 of 3 (job 004; story 9-25 job 007 saw the same). In the ten valid full runs the tier absorbed 0 to 24 frames per run. So the suite cannot show a two-frame delay, and the PASS of the suite says less than the PASS of the other states suites. The reviewer did not sweep +17 ms and did not run the 33 ms mutation on the shared window (-34/+40 ms) of checkbox, switch and radio.

**Approach:** Measure before changing anything. In the private tree make the tier fail (its misses become failures) and run the full suite ten times on macOS through `slot.sh timing` with the load at the start and the end of each run: the failing frames per run are the frames that pass today only because of the tier. Class each of them with a per-frame capture over 150 ms around the failing Web time (value under test, time of the input event, time of each native commit, main-thread blocks of 12 ms or more) in failing and passing runs: a sample taken before the last commit (then the test samples at the wrong time, as story 9-9 showed for the drop), a transition that starts late in the product (then anchor it to the delivered event as the timing fixes in KNOWN-CAUSES.md do), or a main-thread block (say what runs in it). Fix what the measurements show until the suite passes without the tier. Then remove the tier from the test, add the crossing-offset check of the reviewer (state-layer half-crossing native against Chrome, limit 17 ms) and show what the suite catches: mutation runs with the state-layer start delayed by 17, 33 and 50 ms, three runs each. Run the 33 ms mutation once on the checkbox, switch and radio states suites on macOS as well; if one of them passes, file it in DEFECTS.md and do not change that suite here. The test source is shared with iOS: run the list states suite without the tier three times on iPhone 26.3 and twice on iOS 18.6 and class every miss the same way.
