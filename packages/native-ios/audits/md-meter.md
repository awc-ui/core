# md-meter — Swift native parity

A dedicated SwiftUI renderer replaces the generic activity-progress adapter. It implements fourteen properties, seven sparse appearance fields and five measured parts. The source has no events, slots or methods.

## Source and public API mapping

| Source surface | Native implementation |
| --- | --- |
| value, min, max | `AWCMeterReading` supplies the same finite, clamped reading to geometry, text and accessibility. Inverted ranges collapse; empty ranges produce zero fraction. Scaled subtraction prevents overflow for opposite finite extremes, matching the corrected Web source. |
| label, showLabel, showValue, valueText | Raw accessible text is retained. Visible ASCII whitespace follows CSS collapse, with NBSP preserved. Header label shrinks and ellipsizes before the nonshrinking value. A value-only header remains at logical inline start. Circular captions wrap beneath the ring. Unbroken captions overflow from logical start; long circular values remain centered. |
| locale, formatOptions | Public `AWCMeterFormatter.format` calls the system JavaScriptCore `Intl.NumberFormat` with data arguments. There is no WebView, DOM dependency or preview-only preformatted string. Omitted options format the bounded fraction as percent; an explicitly empty object formats the raw reading. Invalid locale/options return the source raw-number string. Nonempty `valueText`, including whitespace, bypasses formatting. Cache keys preserve negative zero. |
| color | Arbitrary valid, case-sensitive theme role identifiers resolve their own color/container tokens independently. Missing roles fall back to primary/secondary-container. Both custom theme tokens and component colors preserve RGBA alpha. |
| variant, size, thickness, density | Linear fills its parent; circular keeps intrinsic ring/caption dimensions. Size clamps, proportional SVG stroke/radius, local versus inherited density, noncanonical inherited density and public zero sizes follow the measured source. RTL mirrors linear fill, while ring arcs remain clockwise and text retains inherited bidirectional paragraph ordering. |
| Seven hooks | `AWCMeterAppearance(indicatorColor:trackColor:trackShape:height:labelColor:valueColor:size:)` and `.awcMeterAppearance` merge inherited fields with local overrides. `AWCCornerShape` retains physical corners, independent elliptical axes and signed point-plus-percentage radii with safe CSS overlap normalization. |
| Five parts | Native inspection exposes actual track, indicator, label, value and circular bounds. Circular track/indicator describe geometric path bounds, excluding the centered stroke. Extreme finite style lengths saturate at the independently measured Chrome used-length limit (16,777,214 units); stroke arithmetic saturates only after it already covers the clipped viewport, and text derives from the effective finite size. Zero-size ring viewports do not invent visible path bounds from the browser's residual SVG geometry. Hidden removes the semantic control and clears inspection. |
| Motion | Retained value changes interpolate geometry for 300ms with cubic-bezier(.2,0,0,1); ring opacity uses an independent 200ms linear transition. Actual asymmetric quarter-arc pixels are identical in LTR and RTL; only the text inherits direction. Retargeting starts from the current presentation value. Reduced motion commits immediately. Native increased contrast uses semantic foreground/gray colors. |
| Accessibility | The actual AppKit responder is a named, read-only level indicator with numeric minimum, maximum, current value and localized value description. It does not become a sequential focus stop or receive pointer input. Decorative glyphs/paths are hidden from accessibility. |

The native text renderer uses actual CoreText glyphs inside the source line boxes, preserving baseline alignment and tabular digits. The independent Arabic font probe identified Geeza Pro Bold fallback with cursive tracking suppression on this macOS/browser combination; its measured width matches the browser without compensating padding or widened tolerance. Mixed-script text receives an explicit inherited paragraph base direction.

## Executed evidence

- Hydrated Chrome reference: **98 configurations per theme**, including ten finite-extreme cases, plus three independently measured long-text overflow cases. Checked-in fixture JSON preserves this evidence separately from native output.
- The standard `test-native-views.sh` runner includes `NativeMeterViewIntegration` and `NativeThemeIntegration`. The full Meter fixture checks actual SwiftUI/AppKit layout, semantic responders, palette/alpha pixels, typography, retained animation, RTL text and hidden transitions. The final run passes **2,669/2,669** checks (225 contracts, 2,444 actual native), plus **30/30** theme checks. Source hashes are recorded in the workspace `swift-evidence.json`.
- **108 independent formatting cases** pass against public native formatting: 75 explicit Node22/ICU78 cases plus 33 earlier V8 cases. They cover rounding modes/increments/priorities, significant/fraction precedence, accounting and rounded zero, compact/scientific/engineering notation, units/currencies/grouping, invalid options and data-only unknown fields. The 98 browser fixtures additionally verify localized accessible text, including Arabic.
- Native theme tests pass **30/30**, including arbitrary role case and alpha. Existing geometry tolerances remain unchanged: 0.03pt layout and 0.8pt text layout for platform font/Chromium quantization; glyph-paint bounds account for ink bearings rather than equating them to typographic advance.
- Both native preview adapters merge all seven appearance fields and use the same authored 300pt centered parent and default value72 as Web. Linear fills that context; circular remains intrinsic. Live-host tests pass **19/19** and cover formatting, defaults/local styles, RTL, roles, actual parts, zero sizes, hidden metadata, and actual captures with 1e308 size/thickness including visible numeric text. They run from the standard native preview runner.
- All three preview products build. A separate snapshot request exercises custom RGBA roles, RTL, unit formatting and asymmetric corners; it creates new evidence rather than rewriting baselines.
- **24 generated Swift examples typecheck**, covering actual properties/options, public appearance/corner APIs and exposed parts. Independent review supplied the RTL and long-text overflow regressions; final commands/logs are recorded alongside the source fixtures.

## Platform boundaries

Executed native evidence is **macOS SwiftUI/AppKit**. This machine has no iOS SDK/Xcode/device runtime, so UIKit compilation, device layout and VoiceOver execution remain unverified. The UIKit semantic adapter supplies a named read-only accessible value; AppKit's explicit level-indicator range APIs are verified only on macOS.

JavaScriptCore's Intl option availability, locale and CLDR data follow the installed Apple OS; the 75-case reference explicitly identifies Node22/ICU78 and does not claim identical locale data on every OS release. Font fallback and antialiasing remain platform dependent. Native increased contrast is an accessibility equivalent, not the same preference as browser CSS forced colors. The extreme used-length cap is this measured Chrome implementation’s limit, not a universal OS layout promise. Structured corner APIs represent native lengths/percentages without evaluating arbitrary CSS strings.
