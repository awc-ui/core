# Android Loading Indicator parity record

Source authority: `packages/core/src/components/md-loading-indicator/` TSX and CSS,
plus the measured browser files in `outputs/native-parity/md-loading-indicator`.
Native implementation: `NativeLoadingIndicator.kt`, `NativeLoadingIndicatorMotion.kt`,
`AWCLoadingIndicatorAppearance.kt`, `AWCCornerShape.kt` and the live host adapter.

## Implemented contract

- All three properties: variant, label and density. Missing/zero density inherits
  the actual ancestor signal, including finite noncanonical values. Local -1 to
  -4 overrides it. Explicit size replaces the density-derived minimum size.
- All five public hooks: color, size, shapeSize, containerColor, containerShape.
  Local overrides merge with inherited defaults, preserve zero and accept RGB/RGBA.
  The shape part has independent native width, height and color styling. There
  are no source events, methods or slots to invent.
- Actual shape width obeys source flex shrink while height remains independent;
  overflowing paint is clipped to the actual host rectangle or contained corners.
  Corners retain physical TL/TR/BR/BL order in RTL, elliptical axes, percentages,
  signed point/fraction combinations and a single CSS overlap scale. Finite
  coefficients that overflow ordinary Double arithmetic use exact decimal
  intermediate arithmetic before normalization; they do not generate NaN geometry.
- The normal animation interpolates the exact source 48-vertex polygons at all
  eight keyframes, per-segment overshoot easing and 1080-degree rotation over
  4.55 seconds. Reduced motion replaces morph/rotation with a circle and the
  source two-second ease-in-out opacity pulse. Hidden/zero-area indicators stop
  frame work; hidden elements have no layout/inspection or accessibility node.
- One native indeterminate progress semantic preserves the raw accessible label
  and polite live-region intent. No visible label or default keyboard tabstop is
  added. Caller-supplied native focus modifiers opt into real focus, which draws
  a 3 dp secondary outline beyond a 2 dp gap, expanding the already-resolved
  physical host corners. No public focus method was invented.
- Reduced motion observes Android's animator setting; failure to register a
  change observer retains the readable system preference. Native forced-palette
  rendering is explicitly opted into through AWCAccessibilityAppearanceScope.
  Android increased contrast is not claimed to be CSS forced-colors mode.
- Opt-in inspection reports actual root and transformed shape layout bounds.
  The live capture bridge keeps only node identities unchanged through committed
  pre-draw and asynchronous PixelCopy completion; unstable parts and orphan
  descendants are omitted. A continuously rotating child therefore does not
  replace valid root geometry or receive a newer box on older captured pixels.

## Verification

- **103 native unit cases passed** in the final unit batch. Five Loading contract
  methods cover typed validation/cascade, density/flex/part sizing, finite extreme
  corners, reduced opacity and **all 16 paused browser animation samples**, each
  with 48 x/y vertices and its rotation matrix. Samples were copied from recorded
  Chromium results rather than generated by the native implementation.
- **84 browser configurations** (42 light + 42 dark) passed actual Compose
  root/shape geometry, RGBA center paint, clipping, rounded/square container
  corners, RTL, inherited density, zero and hidden checks. Geometry tolerance is
  0.51 dp for physical rounding; color tolerance is 0.016 per normalized channel
  for 8-bit alpha/pixel quantization. No tolerance was widened during repairs.
- Device tests passed actual changing morph pixels, transformed inspection,
  stationary reduced-motion circle plus fading pixels, explicit forced palette,
  live label/hidden semantics, no default focus, real caller focus and painted
  focus ring including a fixed 12 dp corner.
- Capture-node stability, the actual live five-hook adapter and zero/hidden host
  states passed. A related host correction centers short components inside the
  100 dp minimum capture surface rather than positioning their shorter content at
  the top. Loading 24 dp, Split 24 dp and Segmented 24 dp are measured at y=38 in
  the 100 dp surface; captured pixels confirm the placement.
- The same device batch verifies the preview-only Segmented listener correction:
  set-mode child mdSegmentClick no longer bypasses the set's propagation stop;
  the log contains exactly its mdChange ordered values array. Public standalone
  and target callbacks remain intact.
- **15 generated public Kotlin examples compiled**, including all hooks, defaults,
  alpha, zero/oversize, typed mixed corners and the 20 x 30 shape part. Exact
  generated sources and compilation evidence are retained outside the repository
  under `outputs/native-parity/md-loading-indicator/examples`.

The first device run passed 2 of 6 methods and failed 4. Its test harness did not
advance the manually frozen frame clock after state changes, attempted a second
configure on a single-use host session, and selected the inner progress semantic
instead of the caller focus target. Those failures are retained. The second run
passed 5 of 6 methods, including all 84 browser cases; its remaining locator
assertion was corrected to the real focusable host. The focused final test passed
1 of 1, including all ring pixel assertions, without changing runtime code or
widening tolerances. Independent review also found and corrected outline corner
expansion and null-corner parser consistency before the second run.

Logs, JUnit records, commands and source hashes are in `audits/evidence/md-loading-indicator`;
full per-attempt snapshots remain under `outputs/native-parity/md-loading-indicator/android`.
Final interactive Laboratory verification is tracked by the integrating task and
is not asserted by these tests.

## Native boundaries

Compose layout rounds to physical pixels and native antialiasing is not identical
to browser rasterization. Native measure dimensions are bounded to 32,766 physical
pixels for valid Compose constraints; inspector dimensions describe what was
actually applied. Normal Laboratory controls and all measured fixtures are well
inside this limit. Rotating part inspection may be absent in captured frames
when its measurement changes during capture; the stable root remains available.
There is no DOM, CSS selector engine or automatic CSS forced-palette environment.
