# Aero flight booking

A responsive React showcase built with the workspace AWC UI core and React packages. Search simulated flights, compare fares, enter traveler details, choose seats and bags, review prices, save itineraries, print them, and cancel bookings.

The app supports one-way and round-trip searches across eight European airports, up to six adult travelers and three fare types. Every flight, fare, seat and payment is demonstration data. There is no airline inventory connection, real charge, actual ticket or outbound email.

## Run and build

From the repository root, install dependencies with `pnpm install`, build the workspace core and React packages, then run:

```sh
pnpm --filter @awc-ui/aero dev
pnpm --filter @awc-ui/aero lint
pnpm --filter @awc-ui/aero test
pnpm --filter @awc-ui/aero build
pnpm --filter @awc-ui/aero test:assets
```

The Vite build emits a static app in `dist/`. Relative URLs and hash navigation let it run under `/showcase/aero/react/`. Fonts and the generated travel banner are bundled locally; font licenses are included with the source assets.

## Demo persistence

Bookings live in this tab's `sessionStorage`, survive reloads and are separate from other independently opened tab sessions. A browser may copy the initial session when duplicating a tab or restore it when restoring a closed tab. Clearing the tab's storage removes these demo bookings. There is no account, backend or shared reservation inventory; use the supplied demo traveler details.

`lib/bookings.mjs` exposes explicit list, create and cancel operations to the UI and WebMCP tools. It retains canonical validated snapshots and calculates prices from the shared flight model rather than trusting submitted totals. Matching request IDs return the original snapshot; changing details for the same ID fails. Cancellation is idempotent. Unavailable storage or failed writes show an error instead of a successful booking.

`lib/flights.mjs` handles origin-airport calendar dates, departed flights, daylight saving changes, fares, optional bags and seat validation. Tests cover these rules together with retry consistency, storage failure, tab isolation and cancellation.

## Existing components

The interface uses the core app bar and tabs, cards, buttons, button groups, segmented controls, autocomplete, date picker, select, text field, checkbox, stepper, lists, tooltip, loading indicator, divider and dialog through `@awc-ui/react`. Seat geometry is domain-specific; every seat uses a core toggle button and public sizing tokens. Theme CSS was generated by AWC UI's theme package and consumes its color, typography, spacing and shape tokens.

Tabs link to semantic panels while React owns screen transitions. The search surface stays mounted while hidden so core selection and focus state persist between visits. `lib/composite-field-enter.mjs` supports native form submission from closed autocomplete inputs while preserving menu selection, IME composition, modifiers and date commitment; its boundary cases have regression coverage.

The static showcase uses the workspace's core text-field formatter fix; it does not patch component prototypes. It carries no duplicate vendored library or unused UI framework scaffold.

WebMCP exposes `search_demo_flights` and `list_demo_bookings` in supporting browsers. These invoke the same flight model and tab-local booking service as the interface.
