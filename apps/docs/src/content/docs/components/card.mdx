elevations, an optional interactive (clickable) mode with ripple, and optional
drag reporting. The host is a `display: flex; flex-direction: column` box with
its own padding and gap — you compose the inside freely.

## When to use

- Grouping **content and actions about one subject** — a product, an article, a
  contact — especially when several appear together as a collection.
- An entry point into a detail view (`interactive`).
- Reorderable tiles (`drag-enabled`).

### When not to use

| Situation | Use instead |
|---|---|
| A vertical list of records | [`md-list`](/components/list/) + [`md-list-item`](/components/list/#the-row--md-list-item) |
| Tabular, comparable data | [`md-table`](/components/table/) |
| A blocking decision | [`md-dialog`](/components/dialog/) |
| A transient message | [`md-snackbar`](/components/snackbar/) |
| Content that spacing or a heading would organise better | Nothing — M3 warns against forcing content into cards |
| Collapsible sections | [`md-accordion`](/components/accordion/) |
| A single action | [`md-button`](/components/button/) |

## There are no named slots

Everything is default-slotted content. There is no `headline`, `media` or
`actions` slot — the card is a container, not a template, and the structure is
yours. The host lays its children out in a column flexbox and reads
`--md-card-padding` and `--md-card-gap` for the spacing — it does not define
them, so they compute to nothing until you set one; the built-in fallbacks are
16px and 8px at density 0 (and taper from there, see
[Density](#every-density-rung)). Plain children stack correctly without a
wrapper.

## Interactive cards

`interactive` makes the whole card the control: the host takes
`role="button"`, `tabindex="0"`, `Enter`/`Space` activation, a state layer and
a ripple, and emits `mdClick`.

:::danger[An interactive card with its own buttons is the classic mistake]
A `button` may not contain focusable content (WAI-ARIA *children
presentational*), so the card defends itself: when the default slot contains
its own focusable controls — native controls, elements with an interactive ARIA
role, or the library's own interactive `md-*` components — the host **silently
drops `role="button"` and `tabindex`** and keeps a plain container role. It
stays mouse-clickable and still ripples, but the keyboard affordance you think
you added is gone.

Decide once: either the card **is** the control, or it **holds** controls.
:::

An `interactive` card also needs a real accessible name. Its inner text is not
automatically a good one — give it `aria-label`.

The ripple is on by default. `ripple="false"` drops the ripple animation and
keeps everything else — the hover, focus and press state layers stay, because
they are a separate element.

|---|---|---|

## Sizing and grids

`full-width` and `full-height` make the card fill its container, which is what
you want inside a CSS grid so cards in a row stay even when translated text
changes their length. For anything more specific there are
`--md-card-width` / `-min-width` / `-max-width` and the matching
`--md-card-height` properties.

It resolves to `block-size: 100%`, and `100%` of an auto-height parent is
nothing at all. It works in the grid above because grid rows give each cell a
definite block-size; in a plain `div` it is a no-op. The same applies to
`full-width` on a shrink-to-fit parent.
:::

Cards are fluid by default, so a card in a responsive grid needs no breakpoint
markup — see the
[responsiveness story](/storybook/?path=/story/containment-card--responsiveness).

## Dragging

`drag-enabled` reports the gesture. It emits `mdDragStart`, `mdDragMove` and
`mdDragEnd`, mirrors the state in `aria-grabbed`, and — once the gesture
actually starts, not merely on pointer-down — applies the dragged state layer
and pins a raised elevation for its duration. It does
translate the card under the pointer and lift it above its siblings for the
duration — but **that transform is undone the instant you release, and nothing
is reordered.** The card tells you what the pointer did; the list is yours.

The gesture only begins once the pointer has travelled 5px or more from where it
went down, so an ordinary click on a `drag-enabled` card is still a click — it
never picks up the dragged visuals — and a real drag suppresses the click that
would otherwise follow it.

:::note[The dragged elevation is not yours to set]
While a card is being dragged the component pins its own elevation — 4 for
`elevated`, 3 for `filled` and `outlined` — so an inline
`--md-card-container-elevation` is ignored for the duration of the gesture and
applies again the moment you let go. M3 asks for the raise; you get it without
wiring it.
:::

## Events

| Event | Cancelable | Detail | Fires |
|---|---|---|---|
| `mdClick` | no | `MouseEvent` | Card activated (pointer, `Enter`, `Space`) — `interactive` only |
| `mdDragStart` | no | `MdCardDragDetail` | Pointer moved past the 5px drag threshold |
| `mdDragMove` | no | `MdCardDragDetail` | Every pointer move during the drag |
| `mdDragEnd` | no | `MdCardDragDetail` | Pointer released |

```ts
interface MdCardDragDetail {
  clientX: number;   // pointer position, viewport coordinates
  clientY: number;
  offsetX: number;   // distance from the drag start point
  offsetY: number;
  startX: number;    // where the gesture began
  startY: number;
}
```

`mdClick` carries the underlying `MouseEvent` as its detail, so
`e.detail.type === 'click'` even when the activation came from the keyboard
path.

Both the drag trio and `mdClick` **bubble** and are **composed**, so one
delegated listener on a wrapper catches every card in a collection. Drag the
right-hand tile and click the left-hand card:

## Accessibility

- **Decide the interaction model once.** Either the card is a control
  (`interactive`, with an `aria-label` and keyboard activation) or it is a
  container holding its own controls. Both at once is the classic
  nested-interactive failure — and the component resolves it by dropping the
  button semantics, not by warning you.
- An `interactive` card needs a real accessible name via `aria-label`. Its
  inner text isn't automatically a good one.
- Headings inside the card should fit the page's heading hierarchy — a card is
  not a reason to restart at `h1`.
- Text over images needs verified contrast; use a bounding shape or a scrim.
- `disabled` leaves the tab order; `soft-disabled` stays focusable, so an
  unavailable-but-worth-discovering card is still reachable.
- Drag is pointer-only. If reordering matters, provide a keyboard path of your
  own.

Tab through these four. The first is a single tab stop that announces as a
button. The second is marked `interactive` too, but its own buttons are the tab
stops — the card detected them and quietly kept a plain container role rather
than nesting focusables inside a `button`. The third is skipped entirely; the
fourth still takes focus and announces its disabled visuals.

[accessibility story](/storybook/?path=/story/containment-card--accessibility)
walks the same roles and keyboard model side by side.

the inline-size bounds all mirror under `dir="rtl"` with nothing re-authored.

content — the card has no named slots, so there is no template doing it for you.
See [RTL](/behaviour/rtl/).

### Every density rung

`density` is a local override of the inherited `data-density`, and the spacing
values all derive from that one signal, so the box tapers together: padding
**16 → 14 → 12 → 10 → 8px**, gap **8 → 7 → 6 → 5 → 4px**, and the body
typescale with them. Padding and gap floor at 8px and 4px rather than
collapsing. The corner radius does **not** taper — it resolves to
`--md-sys-shape-corner-medium`, a flat 12px from the token layer; the
density-scaled value in the CSS is only the fallback for pages that load the
component without those tokens. The card's height does not step evenly either —
tighter padding leaves more room for text, so a card can lose a wrapped line and
jump:

:::caution[There is no `density="0"` reset]
Only rungs `-1` through `-4` exist as rules; the absence of a rung means
"inherit whatever the ancestor says". So `density="0"` on a card inside a
`data-density="-2"` container does **nothing** — it still renders at `-2`. Any
of `-1`…`-4` wins over the inherited rung, tighter or looser; only the default
rung can't be asked for. To get it back, put the card outside the dense subtree.
:::

**Density** — `density="-1…-4"` locally overrides the inherited `data-density`
rung (`0` is the default, not an override). See
[Density](/behaviour/density/).

**i18n** — all text is your slotted content, so translation is entirely yours
(the [localization story](/storybook/?path=/story/containment-card--localization)
shows a translated set). Translated text changes card height; in a grid, prefer
`full-height` so cards in a row stay even.
