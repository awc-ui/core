**A FAB that fans out into 2–6 related actions.** Anchors to an existing
[`md-fab`](/components/fab/) by `id`, morphs that FAB's icon to `close` while
open, and manages the popup's ARIA wiring, roving focus and dismissal.

## When to use

- One prominent creation point that branches into **2–6** related actions —
  new doc / sheet / slide, or photo / video / file.
- All the branches are **positive, creation-flavoured** actions of comparable
  weight.

### When not to use

| Situation | Use instead |
|---|---|
| Exactly one primary action | [`md-fab`](/components/fab/) alone |
| More than ~6 actions | [`md-menu`](/components/menu/), or a dedicated screen |
| Overflow / secondary / destructive actions | [`md-menu`](/components/menu/) from an icon button |
| A screen that already has a toolbar or navigation rail | [`md-menu`](/components/menu/) — M3 says don't pair them |
| Options that select a value rather than trigger an action | [`md-select`](/components/select/) |

## Structure

The FAB is **your** element, referenced by `id`. The menu renders no trigger of
its own.

```html
<md-fab id="create-fab" icon="add" aria-label="Create"></md-fab>

<md-fab-menu anchor="create-fab" placement="up" variant="primary">
  <md-fab-menu-item icon="description" label="Document"></md-fab-menu-item>
  <md-fab-menu-item icon="table_chart" label="Spreadsheet"></md-fab-menu-item>
  <md-fab-menu-item icon="slideshow"   label="Presentation"></md-fab-menu-item>
</md-fab-menu>
```

That is the whole contract: two elements joined by one `id`. The menu can sit
anywhere in the document — it positions itself against the anchor's rect, not
against its own parent:

## What it does to your anchor

While open, the component **writes to your FAB**:

- `aria-expanded`, `aria-haspopup="menu"` and `aria-controls`
- swaps `anchorEl.icon` to `close`, restoring the original on close
- sets `data-shape="circle"`, which applies `border-radius: 50%` — a squared
  icon-only FAB goes round. That is the whole rule: on an `extended` FAB it
  rounds the pill into an ellipse, it does not collapse the label or the width
- sets `--md-fab-container-color` / `--md-fab-icon-color` from the menu's
  `variant`, and removes them again on close

Don't set those yourself, and don't change the anchor's `icon` while the menu
is open — the component saves and restores it around the morph.

## Events & methods

| Event | Cancelable | Detail | Fires | From |
|---|---|---|---|---|
| `mdOpen` | no | `void` | Menu opened | `md-fab-menu` |
| `mdClose` | no | `void` | Menu closed | `md-fab-menu` |
| `mdClick` | no | `void` | An item was pressed | [`md-fab-menu-item`](#the-item--md-fab-menu-item) |

**Methods** — `show()`, `close()`.

`mdClick` comes from the item, not the menu, but it bubbles and is composed, so
one listener on `md-fab-menu` hears every item. Its `detail` is `null` — there
is no `e.detail.value` to read. **Identify the pressed item from `e.target`**,
which is the `md-fab-menu-item` even though you attached the listener to the
menu; `e.currentTarget` is the menu, the element you attached to. Attach per
item instead — as the framework snippets below do — and the handler already
knows which action it is, which is handier when each is a different function.

:::note[The menu closes itself on an item press]
`md-fab-menu-item` only emits `mdClick`. The **menu** listens for it and calls
`close()` plus restores focus to the anchor — so you do not close it yourself,
and calling `close()` in your handler is a redundant no-op.
:::

:::caution[Listen on the menu, not on a shared ancestor]
`md-fab` emits its **own** bubbling, composed `mdClick` (`detail` is the
`MouseEvent`) when the anchor is pressed. A listener on a wrapper around both
elements therefore hears the FAB's press as well as the items'. Bind to the
`md-fab-menu` itself and only the items' `mdClick` reaches you.
:::

## Accessibility

- The popup is `role="menu"` with `aria-orientation="vertical"`. `Escape`
  closes; `ArrowUp`/`ArrowDown` move a roving focus across items.
- Closing **always** returns focus to the anchor FAB, however the menu was
  opened. What is activation-aware is the *opening*: from the keyboard, or from
  a click on an already-focused FAB, focus moves onto the first item; a pointer
  click on an unfocused FAB leaves focus on the anchor and only primes the
  roving tabindex.
- The anchor must be a real, focusable control — the component wires
  `aria-expanded`/`aria-haspopup`/`aria-controls` onto it.
- M3 requires the open menu not to fully obscure another actionable element
  **or its focus indicator**. Verify at your smallest viewport.
- The closed menu is `aria-hidden`, so its items are not announced.

:::caution[Localize `menu-label`]
The popup's own accessible name comes from `menu-label`, which defaults to the
English **`"Actions"`**. A translated app must set it — nothing else names the
`role="menu"` container.

```html
<md-fab-menu anchor="fab" menu-label="Actions de création"></md-fab-menu>
```
:::

## RTL, density & i18n

The stack is vertical, so `placement` never mirrors — `up` stays `up`. What does
mirror is the edge the cluster hangs from: the menu reads the computed
`direction` and pins itself to the anchor's **trailing** edge, so nothing needs
re-authoring between directions. See [RTL](/behaviour/rtl/).

## The item — `md-fab-menu-item`

`md-fab-menu-item` has no page of its own: it is only ever valid as a direct
child of `md-fab-menu`, which owns opening, roving focus and dismissal.
Standalone it renders a row that nothing manages — no keyboard model, no ARIA
menu context, no dismissal.

- **The menu closes itself.** The item emits `mdClick`; `md-fab-menu` listens
  for it, calls `close()` and restores focus to the anchor. Your handler runs
  the action, not the dismissal.
- **`mdClick` has no `detail`** (it is `null`). Read the pressed item off
  `e.target`, which is the `md-fab-menu-item` even when the listener sits on the
  menu — `e.currentTarget` is whatever you attached to.
- `rovingFocusVisible` is set **by the parent** during arrow-key navigation so
  the focus ring appears on the roved item even when DOM focus hasn't moved.
  Don't set it yourself.
- Both `disabled` and `soft-disabled` block activation and grey the row.
  `disabled` additionally sets `pointer-events: none`, so it cannot be clicked
  or hovered. **Neither removes the item from the menu's keyboard model**: the
  menu's roving tabindex and its arrow / `Home` / `End` / typeahead navigation
  walk *every* item, so a disabled branch is still reachable and announced
  (`aria-disabled="true"`). Prefer omitting an action you never want reached.
- The `label` prop and the default slot are alternatives: `label` wins, and the
  slot is the fallback when it is empty.
