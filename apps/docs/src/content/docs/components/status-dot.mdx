## When to use

:::note[Not a Material Design 3 component]
M3 has badges, not status dots. The guidance on this page is **house rules**,
derived from M3's badge guidance plus general status-indicator practice — there
is no M3 status-dot page to cite.
:::

- **Presence**: online / away / busy / offline / invisible on an avatar.
- A compact **health or state** marker in a dense list or table row.

### When not to use

| Situation | Use instead |
|---|---|
| A count of unread items | [`md-badge`](/components/badge/) |
| An interactive filter or tag | [`md-chip`](/components/chip/) |
| A status with a text label the user reads | [`md-chip`](/components/chip/) |
| Progress or loading | [`md-progress-indicator`](/components/progress-indicator/) / [`md-loading-indicator`](/components/loading-indicator/) |
| A large, prominent state banner | [`md-card`](/components/card/) with a semantic colour |
| Something clickable | [`md-button`](/components/button/) / [`md-icon-button`](/components/icon-button/) |

:::tip[Dot vs badge]
A status dot is **presence**; [`md-badge`](/components/badge/) is a **count**.
If the answer to "what does it show?" is a number, you want the badge.
:::

## Positioning

The dot **positions itself absolutely** at the bottom inline-end corner of its
containing block, using `--md-status-dot-inset-end` and
`--md-status-dot-inset-block-end` (both `0` at `small` and `medium`, `-3px` at
`large` so the bigger dot still kisses the tile edge).

:::caution[The parent needs `position: relative`]
Without a positioned ancestor the dot anchors to the nearest one further up the
tree — often the page — and lands somewhere unrelated to its subject. Wrap the
avatar (or row, or tile) in a `position: relative` element.
:::

```html
<span style="position: relative; display: inline-flex;">
  <md-avatar name="Ada Lovelace"></md-avatar>
  <md-status-dot state="online" label="Online"></md-status-dot>
</span>
```

The insets are **logical**, so the dot flips to the correct corner under
`dir="rtl"` with no extra CSS. A surface-coloured outline (`2px` at `medium`,
`1.5px` at `small`, `3px` at `large`) keeps it visually detached from whatever
it sits on.

### Match the anchor to the tile shape

The default offset is tuned for a **circular** avatar, where the corner of the
box sits outside the drawn shape. On a rounded or square tile the same offset
puts the dot *inside* the silhouette, overlapping the radius — push it further
out so it kisses the corner instead.

### Inline, without an anchor

In a legend, a status menu or a dropdown row the dot is not decorating a tile —
it is content in its own right. Override `position: static` and it detaches from
corner-anchoring and flows like any inline element.

## States

Six presence states, each with its own fill and pulse colour.

| `state` | Meaning |
|---|---|
| `online` | Available |
| `away` | Idle |
| `busy` | Do not disturb / in a call |
| `offline` | Not connected |
| `invisible` | Connected but **appearing** offline — a hollow ring on a surface fill |
| `neutral` | **Default.** No presence semantics |

  <span style="position: relative; display: inline-flex; width: 24px; height: 24px;"><md-status-dot state="invisible" label="Invisible"></md-status-dot></span>

  label="online, away, busy, offline, invisible, neutral"
/>

:::danger[Without `label` the dot is silent to assistive tech]
With an empty `label` (the default) the dot renders as
`role="presentation"` + `aria-hidden="true"`. Colour then becomes the *only*
signal of state, which fails **WCAG 1.4.1 Use of Colour** on its own — and in
Windows High Contrast every state collapses to one system colour. Treat `label`
as required, unless the parent element's own text already says the state.
:::

:::caution[`state="invisible"` is a semantic, not `display: none`]
It means "the user appears offline" and renders a visible hollow ring. To hide
the indicator, **remove the element** — don't reach for `invisible`.
:::

:::danger[`live` animates — it does not announce]
The prop's name is about **motion**, not about ARIA. Nothing you do to `state`
is spoken as a result of setting `live`: the dot's accessible name comes from
`aria-label`, and changing an `aria-label` is not a live-region content change.
If a state transition matters to a screen-reader user, publish it yourself
through your own `aria-live` region — see below.
:::

Each state pulses in **its own colour** — green pulses green, busy pulses red —
so the halo never contradicts the dot.

Only `online`, `away` and `busy` ship a halo colour, though. The base
`--_pulse-color` is `transparent`, so `live` on **`offline`, `invisible` or
`neutral` animates nothing you can see** — the animation runs, but the halo it
interpolates is invisible. That is deliberate (a dot that is offline is not
"live"), and if you do want one, set `--md-status-dot-pulse-color` yourself, as
the fourth dot in that row does. `invisible` is the odd one out even then: its
inset ring is drawn over by the pulse keyframe, so the two conflict visually.

`--md-status-dot-pulse-duration` sets the period (default `1.6s`).

The pulse is gated behind `prefers-reduced-motion: no-preference`, so users with
reduced motion enabled at the OS level see a static dot — no opt-out prop
needed, and nothing to configure.

Since the component will not announce for you, pair it with a live region that
you update alongside the dot. Switch presence below: the dot recolours, its
`label` follows, and the region — visible here, visually hidden in production —
is what a screen reader actually reads out.

for colour-blind readers and in a printed table alike.

## Accessibility

- **`label` is effectively required.** Empty (the default) →
  `role="presentation"` + `aria-hidden="true"`, i.e. invisible to assistive
  tech, with colour as the only cue. The one acceptable exception is a dot that
  decorates an element whose own accessible name already carries the state
  (`<md-avatar label="Ada Lovelace, online">`).
- With a `label` and `live` off, the dot becomes `role="img"` with that label —
  a static, named status image.
- With a `label` and `live` on, it becomes `role="status"`. That role does not
  rescue you: the name comes from `aria-label`, not from text content, so
  presence *changes* still need your own live region.
- The dot is **not focusable** and has no interactive role. Don't attach click
  handlers — use [`md-icon-button`](/components/icon-button/) if the indicator
  must be actionable.
- **WCAG 1.4.1** — never let the six state colours be the only signal. Under
  Windows High Contrast they all collapse to one system colour.
- Honour reduced motion: the pulse is already gated behind
  `prefers-reduced-motion`, and you can drop `live` or override
  `--md-status-dot-pulse-duration`.

The three exposure modes side by side — the first is invisible to assistive
tech, the other two are named:

### Density and direction together

The two are independent signals, so they compose without any extra wiring — a
global `data-density` ancestor sets the rung, `dir` sets the corner. The second
dot in each row takes `density="-4"`, tightening past the inherited `-2`; the
third resets to full size with an inline `--md-sys-density-scale: 0`, which is
the only thing that actually escapes the ambient rung:

:::caution[`density="0"` does not undo an inherited rung]
The rungs are declared as `:host([density='-1'])` … `:host([density='-4'])`,
and `0` — the prop's default — has no rule of its own. Inside a
`data-density="-2"` ancestor, `density="0"` therefore changes nothing: the dot
keeps inheriting `-2`. `density` tightens past the ambient rung, it does not
reset to base. To get a full-size dot inside a dense region, move it out of the
dense subtree or set `--md-sys-density-scale: 0` on a wrapper.
:::

**Density** — `density="-1…-4"` locally overrides the inherited `data-density`
rung, shrinking the dot and its outline together. See
[Density](/behaviour/density/).

**i18n** — `label` is user-facing text. Translate it, along with the state names
("Away", "Busy") in your dictionary, and let `dir` come from the document rather
than hard-coding a corner.
