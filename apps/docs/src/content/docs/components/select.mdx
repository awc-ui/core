**Pick exactly one value from a list.** A [`md-text-field`](/components/text-field/)
trigger with a [`md-menu`](/components/menu/) dropdown, optional in-menu
filtering, async option loading, and **row virtualization** for large lists.
Form-associated via `ElementInternals`, with full constraint validation.

:::note[Not a Material Design 3 component]
M3 has no select page: it specs the [text field](/components/text-field/) and
the [menu](https://m3.material.io/components/menus/guidelines) this component is
assembled from, but not the picker itself. The listbox semantics, the filtering
and the virtualization are this library's own contract, and the guidance below
is **house rules** informed by M3's menu and text-field specs.
:::

## When to use

- **One** value from a list of roughly **5 or more** options.
- Options are known — static, fetched, or filtered server-side.
- Space is constrained: the list should stay collapsed until needed.

### When not to use

| Situation | Use instead |
|---|---|
| Five or fewer options that should all be visible | [`md-radio`](/components/radio/) |
| Several values may be chosen | [`md-select-option`](/components/select/#md-select-option) ·
[`md-multi-select`](/components/multi-select/) |
| The user types free text with suggestions | [`md-autocomplete`](/components/autocomplete/) |
| 2–5 exclusive view/mode options | [`md-segmented-button`](/components/segmented-button/) |
| A date or a time | [`md-date-picker`](/components/date-picker/) / [`md-time-picker`](/components/time-picker/) |
| Running actions rather than choosing a value | [`md-menu`](/components/menu/) |
| A boolean | [`md-switch`](/components/switch/) / [`md-checkbox`](/components/checkbox/) |

### Decision cues

| Need | Setting |
|---|---|
| Options written in markup | `md-select-option` children |
| Options from data or a fetch | The `options` **property** |
| Filled field | `variant="filled"` |
| A clear affordance | `clearable` |
| An in-menu search box | `filterable` |
| Thousands of rows | `virtualize` |
| Menu as wide as the trigger | `match-trigger-width` |
| Compact trigger and rows | `density="-1…-4"` |

## Authoring the options

:::caution[Two sources — never mix them]
Use **either** [`md-select-option`](/components/select-option/) children **or**
the `options` array property. Two sources of truth fight each other.
:::

Arrays don't cross the attribute boundary, so `options` must be set as a JS
**property**:

<ComponentDemo
  html={`<md-select id="opts-sel" label="Country" style="min-inline-size: 260px;"></md-select>`}
  script={`
  var el = root.querySelector('#opts-sel');
  var countries = [
    { code: 'fr', name: 'France' },
    { code: 'de', name: 'Germany' },
    { code: 'ro', name: 'Romania' },
    { code: 'nl', name: 'Netherlands' },
  ];
  el.options = countries.map(function (c) { return { value: c.code, label: c.name }; });
  el.value = 'de';`}
  htmlForCode={`<md-select id="country" label="Country"></md-select>

<script type="module">
  const select = document.getElementById('country');

  // Arrays don't cross the attribute boundary — set it as a property.
  select.options = countries.map((c) => ({ value: c.code, label: c.name }));
  select.value = 'de';
</script>`}
  label="options set as a JS property — no markup children"
  storyId="selection-select--playground"
/>

`value` is a **single string**, not an array. `getLabels(values)` resolves
values back to display labels.

`md-select-option` is a **declarative data carrier**, shared with
[`md-multi-select`](/components/multi-select/). It renders **nothing**
(`:host { display: none }`) — the parent reads its props and projects them into
its own [`md-menu`](/components/menu/) as real `md-menu-item` rows.

<ComponentDemo
  html={`<md-select label="Priority" value="med" style="min-inline-size: 260px;">
  <md-select-option value="low" icon="arrow_downward">Low</md-select-option>
  <md-select-option value="med" icon="remove">Medium</md-select-option>
  <md-select-option value="high" icon="arrow_upward" icon-color="var(--md-sys-color-error)">High</md-select-option>
</md-select>`}
  label="Markup-authored options — open it to see the rows the carriers describe"
  storyId="selection-select--with-icons"
/>

- **It is a carrier, not the rendered row.** In devtools it is an empty, hidden
  host — that is correct, and it means the option never flashes unstyled before
  hydration. **Style the parent, not the carrier**: the visible row lives in the
  select's `md-menu`, so reach it with the select's parts and custom properties.
- `label` falls back to the **slotted text** when it is empty.
- **`selected` is a hint** — honoured only while the parent's own `value` is
  unset. If the select has a value, the select wins.
- Adding and removing options at runtime works; connect / disconnect trigger a
  re-read.
- Give every option a unique, stable `value`. Matching and every emitted payload
  depend on it — translate the label and `supporting-text`, keep `value`
  untranslated.

:::caution[`mdSelectOptionChange` is not for you]
It fires on `connectedCallback`, `disconnectedCallback` and any watched prop
change so the parent can re-read its option set. **It is the internal
parent↔child sync channel** — listen to the select's `mdChange` instead.
:::

## Clearable, filterable & loading

`clearable` adds a clear affordance. `filterable` renders a search box **inside
the menu** — turn it on past roughly 15 options. `loading` shows the progress
affordance while options are being fetched.

`filterable` works whichever way the options were supplied. A plain list filters
client-side on **label or supporting text**, case-insensitively and immediately;
a virtualized one filters inside the WASM engine, debounced, with a spinner. No
match shows `no-results-text`, and closing the menu clears the query — the field
is uncontrolled and unmounts with the menu, so reopening shows the full list.

For server-side search, combine `setQuery()` with `loadOptions()` and drive
`loading` yourself. `setQuery(q)` filters the menu exactly as typing into the
in-menu search field would, and fills that field with `q` so the two agree —
call it **after** `loadOptions()` resolves, since loading replaces the whole
option set and would overwrite the filter.

<ComponentDemo
  html={`<div style="display:flex; flex-direction:column; gap:8px; align-items:flex-start;">
  <div style="display:flex; gap:12px; align-items:center; flex-wrap:wrap;">
    <md-select id="server-sel" label="Airport" filterable loading-text="Searching…" style="inline-size: 280px; flex: 0 0 auto;"></md-select>
    <md-button data-server-q variant="outlined" size="xs">setQuery('fra')</md-button>
  </div>
  <output data-server-out style="font:12px/1.6 ui-monospace,SFMono-Regular,Menlo,monospace; opacity:.85;">Open it — the first page loads on mdOpen.</output>
</div>`}
  script={`
  var el = root.querySelector('#server-sel');
  var out = root.querySelector('[data-server-out]');
  var ALL = [
    { value: 'fra', label: 'Frankfurt (FRA)' },
    { value: 'cdg', label: 'Paris Charles de Gaulle (CDG)' },
    { value: 'lhr', label: 'London Heathrow (LHR)' },
    { value: 'ams', label: 'Amsterdam Schiphol (AMS)' },
    { value: 'otp', label: 'Bucharest Otopeni (OTP)' },
  ];
  // Stands in for a paged endpoint.
  var fetchPage = function (q) {
    return new Promise(function (resolve) {
      setTimeout(function () {
        var needle = (q || '').toLowerCase();
        resolve(ALL.filter(function (o) {
          return o.label.toLowerCase().indexOf(needle) !== -1;
        }));
      }, 500);
    });
  };
  var load = function (q) {
    el.loading = true;
    out.textContent = 'GET /airports?q=' + JSON.stringify(q || '');
    return fetchPage(q).then(function (rows) {
      // Chain on loadOptions itself — it resolves when the store has finished
      // packing. Filtering before that runs against a store still loading.
      return el.loadOptions(rows).then(function () {
        el.loading = false;
        out.textContent = 'GET /airports?q=' + JSON.stringify(q || '') + ' → ' + rows.length + ' rows';
      });
    });
  };
  // Fetch once, and keep the promise: loadOptions() replaces the whole option
  // set, so anything that filters has to wait for it or it gets overwritten.
  var loaded = null;
  var ensureLoaded = function () {
    if (!loaded) loaded = load('');
    return loaded;
  };
  el.addEventListener('mdOpen', ensureLoaded);
  root.querySelector('[data-server-q]').addEventListener('click', function () {
    el.show();
    ensureLoaded().then(function () { el.setQuery('fra'); });
  });`}
  htmlForCode={`<md-select id="airport" label="Airport" filterable loading-text="Searching…"></md-select>

<script type="module">
  const select = document.getElementById('airport');

  const load = async (q) => {
    select.loading = true;
    // await it: loadOptions resolves once the store has finished packing, and
    // filtering before that runs against a store that is still loading.
    await select.loadOptions(await fetchPage(q));   // your endpoint
    select.loading = false;
  };

  // Fetch the first page when the menu opens, once — loadOptions() replaces the
  // whole option set, so a later fetch would overwrite an applied filter.
  let loaded = null;
  const ensureLoaded = () => (loaded ??= load(''));
  select.addEventListener('mdOpen', ensureLoaded);

  // …and drive the in-menu search box yourself when you have a query.
  // setQuery() filters the menu AND fills the search field, exactly as typing
  // would — after the options are in.
  await ensureLoaded();
  select.setQuery('fra');
</script>`}
  label="Fetch on open, then setQuery('fra') filters the menu and fills the search box"
  storyId="selection-select--async-loading"
/>

## Width & menu placement

`match-trigger-width` (on by default) ties the menu to the field's width; set
`match-trigger-width="false"` to let the menu size itself. `full-width`
stretches the trigger to its container, and `placement="top-start"` opens
upward. Give the menu a sensible `max-height` so it stays reachable on short
viewports.

## Virtualization

`virtualize="auto"` turns on row virtualization past an internal threshold;
`"always"` forces it.

:::caution[Give virtualized rows a stable `row-height`]
If your rows aren't uniform and `row-height` doesn't match, the scroll position
drifts.
:::

<ComponentDemo
  html={`<div style="display:flex; flex-direction:column; gap:8px; align-items:flex-start;">
  <md-select id="virt-sel" label="Option" filterable virtualize="always" row-height="48" max-height="320" style="min-inline-size: 300px;"></md-select>
  <p data-virt-status style="font:500 12px/16px Roboto,system-ui,sans-serif; color:var(--md-sys-color-on-surface-variant); margin:0; min-block-size:16px;"></p>
</div>`}
  script={`
  var el = root.querySelector('#virt-sel');
  var status = root.querySelector('[data-virt-status]');

  // JS objects, so this is a WASM load rather than an array allocation.
  el.loading = true;
  status.textContent = 'Loading 10,000,000 options…';
  var t0 = performance.now();
  el.loadOptions({
    count: 10000000,

  }).then(function () {
    el.loading = false;
    status.textContent =

## Events

| Event | Cancelable | Detail | Fires |
|---|---|---|---|
| `mdChange` | no | `string` | The selected value changed |
| `mdOpen` | no | `void` | The dropdown opened |
| `mdClose` | no | `void` | The dropdown closed |
| `mdValidityChange` | no | `{ valid, validationMessage, flags }` | Validity changed |

:::danger[Two different composition rules on one element]
`mdValidityChange` is **not composed** — deliberately, so the embedded
`md-text-field`'s validity doesn't leak out. Listen for it on `md-select`
itself. `mdOpen` / `mdClose` **are** composed, so they also fire on an
embedding shadow host at `AT_TARGET`; guard against double handling if you wrap
this component.
:::

## Accessibility

- `label` supplies the accessible name. The dropdown is a `md-menu` with
  managed roving focus; `Escape` closes and returns focus to the trigger.
- Typeahead and arrow navigation are handled internally.
- Because ARIA IDREFs can't cross shadow boundaries, the trigger uses
  `aria-haspopup` rather than a full `combobox` / `aria-activedescendant`
  wiring. **Don't try to add those from outside — they won't resolve.**
- Errors appear in the supporting line; keep `reserve-supporting-space` on in
  dense forms so the layout doesn't jump.
- Set `max-height` so the menu stays reachable on short viewports.

### Keyboard

| Key | Action |
|---|---|
| `Enter` / `Space` / `↓` | Open the menu from the trigger |
| `↑` / `↓` | Move between options |
| `Home` / `End` | First / last option |
| `Enter` | Commit the focused option and close |
| A–Z | Typeahead, or types into the search box when `filterable` |
| `Escape` | Close, returning focus to the trigger |

## Theming

| Custom property | Purpose |
|---|---|
| `--md-select-width` / `--md-select-min-width` | Trigger width |
| `--md-select-caret-color` / `--md-select-caret-size` | Dropdown caret |

| `--md-select-trailing-gap` | Spacing of trailing controls |
| `--md-select-option-icon-color` | Option row icons |
