**Pick several values from a list.** Everything
[`md-select`](/components/select/) does, plus multiple selection rendered as
chips / a count / plain text, an optional select-all row, a selection cap, and
a field-or-button trigger. Form-associated via `ElementInternals`.

:::note[Not a Material Design 3 component]
M3 has no multi-select page, and no multi-selection pattern for a
[menu](https://m3.material.io/components/menus/guidelines) at all. The chips,
the select-all row, the selection cap and the listbox semantics are this
library's own contract; the guidance below is **house rules** informed by M3's
menu, chip and text-field specs.
:::

## When to use

- **Several** values from a list of roughly 5+ options.
- The chosen values should stay visible (as chips) after the menu closes.
- Optionally capped with `max-selected`, or with a select-all shortcut.

### When not to use

| Situation | Use instead |
|---|---|
| Exactly one value | [`md-select`](/components/select/) |
| Few options, all worth showing | [`md-checkbox`](/components/checkbox/) group |
| Assigning a subset from a large pool, side by side | [`md-transfer-list`](/components/transfer-list/) |
| Free text with suggestions | [`md-autocomplete`](/components/autocomplete/) |
| A handful of toggleable filters | [`md-chip`](/components/chip/) set |
| 2–5 exclusive options | [`md-segmented-button`](/components/segmented-button/) |

The same two option sources as `md-select` apply — declarative
[`md-select-option`](/components/select-option/) children **or** the `options`
array property, never both.

### Decision cues

| Need | Setting |
|---|---|
| Chips inside the field | `display="chips"` |
| A "3 selected" summary | `display="count"` |
| Chips below the field | `display="chips-inline"` |
| A button instead of a field | `trigger="button"` |
| A "select all" row | `select-all` |
| A hard limit | `max-selected` |
| An in-menu search box | `filterable` |
| Compact trigger, chips and rows | `density="-1…-4"` |

### Bring your own trigger

`trigger="button"` is a convenience, not a ceiling. Put **any element** in
`slot="trigger"` and it becomes the opener: the built-in field / button is not
rendered at all, and the chips keep their `chip-position` relationship to
whatever you supplied. The opener sits outside the component's own chrome
without losing the chip layout.

<ComponentDemo
  html={`<md-multi-select label="Tags" chip-position="right" chip-overflow="wrap">

  <md-select-option value="a" selected>Alpha</md-select-option>
  <md-select-option value="b">Beta</md-select-option>
  <md-select-option value="c">Gamma</md-select-option>
</md-multi-select>

<md-multi-select label="Filters" chip-position="right" chip-overflow="wrap">
  <md-icon-button slot="trigger" variant="tonal" icon="filter_list" aria-label="Filter"></md-icon-button>
  <md-select-option value="open" selected>Open</md-select-option>
  <md-select-option value="mine">Assigned to me</md-select-option>
  <md-select-option value="urgent">Urgent</md-select-option>
</md-multi-select>`}
  label="An md-button and an md-icon-button as triggers — same chips, same menu"
  storyId="selection-multi-select--slotted-trigger"
/>

The component wires the element it is given rather than re-rendering it: a click
opens the menu, an `id` makes it the menu's anchor, and `aria-haspopup="listbox"`
advertises the popup (`aria-expanded` follows on triggers whose role supports it).
`Escape` closes and returns focus to it.

:::caution[What a slotted trigger does not inherit]
`disabled`, `error` and `required` still drive the component's own state and
validity, but they cannot restyle an element the component does not render —
mirror `disabled` onto your trigger yourself. The supporting / error line is
still rendered below, announced via `role="alert"` rather than
`aria-describedby`: that IDREF would have to cross the shadow boundary, where it
cannot resolve.
:::

## Select all & the selection cap

`show-select-all` adds a select-all row. `max-selected` caps the selection —
and the value that means "no cap" is **`0`**.

:::danger[`max-selected="0"` means unlimited, not "none allowed"]
A common and costly misreading. To block selection entirely, use `disabled`.
:::

When the cap is reached the component **rejects** further selections. Because
`md-menu-item` / `md-checkbox` self-toggle on click *before* the parent
reconciles, a rejected pick has to be reverted via the event target — the
component does this internally, but if you wrap it in your own controlled
layer, replicate it or you will get a phantom check.

## Virtualization

`virtualize="always"` hands the option set to the WASM-backed store: rows stream
in through a factory instead of existing as JS objects, and only the visible
window is ever in the DOM. Filtering and typeahead run in the same store, so a
query over ten million rows is not a JS array scan.

Same caveat as `md-select` — give non-uniform rows a stable `row-height`, or the
scroll position drifts.

<ComponentDemo
  html={`<div style="display:flex; flex-direction:column; gap:8px; align-items:flex-start;">
  <md-multi-select id="virt-ms" label="Option" filterable show-select-all display-mode="count" virtualize="always" row-height="48" max-height="320" style="min-inline-size: 300px;"></md-multi-select>
  <p data-virt-status style="font:500 12px/16px Roboto,system-ui,sans-serif; color:var(--md-sys-color-on-surface-variant); margin:0; min-block-size:16px;"></p>
</div>`}
  script={`
  var el = root.querySelector('#virt-ms');
  var status = root.querySelector('[data-virt-status]');
  // Ten million rows, streamed through the row factory — they never exist as
  // JS objects, so this is a WASM load, not an array allocation.
  el.loading = true;
  status.textContent = 'Loading 10,000,000 options…';
  var t0 = performance.now();
  el.loadOptions({
    count: 10000000,
    getRow: function (i) { return { value: 'v' + i, label: 'Option ' + i }; },
  }).then(function () {
    el.loading = false;
    status.textContent =
      'Ready — 10,000,000 options in ' + Math.round(performance.now() - t0) + ' ms.';
  });`}
  htmlForCode={`<md-multi-select
  id="options"
  label="Option"
  filterable
  show-select-all
  display-mode="count"
  virtualize="always"
  row-height="48"
  max-height="320"
></md-multi-select>

<script type="module">

  // A row factory streams into WASM — ten million options never exist as JS
  // objects at once. Flip the loading flag around it so the trigger says so.
  el.loading = true;
  await el.loadOptions({
    count: 10_000_000,

## Events

| Event | Cancelable | Detail | Fires |
|---|---|---|---|
| `mdChange` | no | `string[]` | The selection changed — carries the **new full array** |
| `mdRemove` | no | `string` | A chip's × removed one value |
| `mdClear` | no | `void` | The clear affordance was used |
| `mdOpen` | no | `void` | The dropdown opened |
| `mdClose` | no | `void` | The dropdown closed |
| `mdValidityChange` | no | `{ valid, validationMessage, flags }` | Validity changed |

:::caution[Don't double-handle a removal]
`mdRemove` fires with the single removed value, and `mdChange` still fires with
the new full array. Treat `mdChange` as the source of truth.
:::

`mdValidityChange` is **not composed** — listen on the element itself.
`mdOpen` / `mdClose` **are** composed, so they also fire on an embedding shadow
host at `AT_TARGET`.

## Accessibility

- `label` names the control. The menu is a managed listbox with a `live-region`
  part, so selection changes are announced.
- Each chip's remove affordance needs a name that includes the value's label,
  so "Remove" isn't ambiguous across many chips.
- `Escape` closes the menu and returns focus to the trigger.
- As with `md-select`, full `combobox` ARIA can't be wired across the shadow
  boundary — **don't attempt it from outside.**
- Announce cap rejections through `supporting-text` / `error-text`; a silent
  rejection is invisible to screen-reader users.

### Keyboard

| Key | Action |
|---|---|
| `Enter` / `Space` / `↓` | Open the menu from the trigger |
| `↑` / `↓` | Move between options |
| `Home` / `End` | First / last option |
| `Enter` / `Space` | Toggle the focused option — the menu **stays open** |
| A–Z | Typeahead, or types into the search box when `filterable` |
| `Escape` | Close, returning focus to the trigger |
| `Backspace` | On a focused chip, remove it |

## RTL, density & i18n

**RTL** — field, chips, caret and menu mirror under `dir="rtl"`. `placement` is
logical; `chip-position="left"` / `"right"` is **physical**, so re-check it per
direction. See [RTL](/behaviour/rtl/).

:::caution[`chip-position` is physical, `placement` is logical]

you. `chip-position="left"` / `"right"` means **left** and **right** on screen —
it does not flip under `dir="rtl"`. Re-check it per direction, or leave it at
the default.
