**The library's single text-entry primitive.** Filled and outlined, single-line
or auto-growing, with built-in clear / password-toggle / speech affordances,
input masking via `formatter` / `parser`, debounced search, and the full
constraint-validation API — form-associated via `ElementInternals`.

## When to use

- **Any** free-text or numeric entry: names, emails, passwords, amounts,
  comments.
- Multi-line entry (`multiline="auto-grow"` or `"fixed"`).
- As the input surface inside a composite you're building.

### When not to use

| Situation | Use instead |
|---|---|
| Entry with a suggestion list | [`md-autocomplete`](/components/autocomplete/) |
| App-wide search with a results surface | [`md-search`](/components/search/) |
| Choosing from a fixed set | [`md-select`](/components/select/) / [`md-multi-select`](/components/multi-select/) |
| A date or a time | [`md-date-picker`](/components/date-picker/) / [`md-time-picker`](/components/time-picker/) |
| A bounded numeric range the user should feel | [`md-slider`](/components/slider/) |
| A colour | [`md-color-picker`](/components/color-picker/) |
| Rich text | Not in this library — integrate a third-party editor |
| A yes / no | [`md-checkbox`](/components/checkbox/) / [`md-switch`](/components/switch/) |

## Variants

| Variant | Container | Use for |
|---|---|---|
| `filled` | Tonal fill + bottom active indicator | **Default.** Dense forms, surfaces that need the field to read as a distinct target |
| `outlined` | Transparent, notched outline | Sparse layouts, forms over patterned or coloured surfaces |

:::caution[The default is `filled`, not `outlined`]
M3 also says the two shouldn't be mixed: separate them by region, and don't put
both in the same form.
:::

## States & the message line

| State | Focusable | Use when |
|---|---|---|
| Default | **Yes** | Normal entry |
| `error` + `error-text` | **Yes** | The value failed validation — set **both** |
| `readonly` | **Yes** | The value is shown for reading and copying, not editing |
| `disabled` | No | The control is unavailable in this context |

:::danger[`error-text` **replaces** `supporting-text`]
That's by design, matching M3 — don't try to show both. And setting
`error-text` alone doesn't turn the field red: **set `error` too.**
:::

Without `reserve-supporting-space` the message line only exists when there's a
message, so content below shifts when an error appears. Turn it on in dense
forms.

## Affordances: clear, password toggle, speech

| Prop | Values | Use for |
|---|---|---|
| `clearable` | `"internal"` / `"external"` / `false` | A clear icon button. `internal` empties `value` itself; `external` only emits `mdClear` and leaves the value to you |
| `password-toggle` | `"internal"` / `"external"` / `false` | A visibility toggle. `internal` flips the input `type` itself; `external` only emits `mdPasswordToggle` and leaves the type to you |
| `speech-to-text` | `"internal"` / `"external"` / `false` | A mic button. `internal` drives the browser's SpeechRecognition and appends the transcript; `external` only emits `mdSpeechResult`, so you can run your own engine |

:::danger[`"external"` does not move the button outside the field]
All three modes render the **same** in-field icon button. What `"external"`
changes is **who owns the mutation**: the component stops touching `value`,
`type` or recognition and emits its event instead, so a controlled parent can do
the work. Choose `"external"` and forget to handle the event and you get a
button that visibly does nothing.
:::

Writing the bare attribute — `clearable`, `password-toggle` or `speech-to-text`
with no value — is normalised to `"internal"` on load, so it is a supported
shorthand rather than a silent off.

## Masking with `formatter` / `parser`

`formatter` and `parser` are **function props** — assign them in JS, they can't
cross the attribute boundary. They are a pair: `formatter` renders the display
value, `parser` converts it back.

:::tip[`value` is always the parsed value]
`formatter` only affects display. `value`, `mdInput` and `mdChange` all carry
the parsed value. `format-on="blur"` is the default, and it avoids fighting the
caret. `format-on="input"` needs a `parser` — without one the component falls
back to blur formatting and warns in dev.
:::

```js
field.formatter = (raw) => new Intl.NumberFormat('en-US').format(Number(raw));
field.parser    = (shown) => shown.replace(/,/g, '');
```

## Debounce & throttle

`debounce` and `throttle` gate **`mdSearch`** — not `mdInput`. `mdInput` always
fires on every keystroke; `mdSearch` is the rate-limited twin you point at an
API call. The usual search-as-you-type setup is `debounce="300"`. Clearing the
field re-emits `mdSearch` with an empty string, so stale results get dropped.

:::caution[`debounce` does not slow `mdInput` down]
It only gates `mdSearch`. If you listen to `mdInput` and expect the delay you
will fire one request per keystroke. Listen to `mdSearch` instead.
:::

## Events

| Event | Vetoable | Detail | Fires |
|---|---|---|---|
| `mdInput` | no | `string` | On every keystroke — **never** debounced or throttled |
| `mdChange` | no | `string` | On commit (blur / `Enter`), and when the field is cleared |
| `mdSearch` | no | `string` | Same trigger as `mdInput`, but gated by `debounce` / `throttle`, de-duplicated against the last emitted value, and re-emitted as `''` on clear |
| `mdClear` | no | `void` | The clear affordance was used (icon or `Escape`) |
| `mdPasswordToggle` | no | `{ visible }` | Password visibility toggled |
| `mdSpeechResult` | no | `{ transcript, listening }` | Speech recognition update |
| `mdValidityChange` | no | `{ valid, validationMessage, flags }` | Validity changed — **not composed** |

These are notifications, not hooks — `preventDefault()` on any of them is a
no-op (unlike [`md-button`](/components/button/)'s `mdClick`). Cancel at the
source instead: `restrict` to block characters, or `setCustomValidity()` to
reject a value.

:::caution[`mdValidityChange` is `composed: false` on purpose]
So that composites like [`md-select`](/components/select/), which embed a text
field, don't leak the inner control's validity. It still **bubbles**, so a
light-DOM ancestor — a `<form>`, an app root — hears every control beneath it.
What `composed: false` blocks is escaping the shadow root of a composite that
embeds the field: from outside one of those, bind on the field itself.
:::

## Forms & validation

`md-text-field` is **form-associated** via `ElementInternals`, so `name` puts
the value into `FormData` across the shadow boundary — no hidden `<input>`
needed. `required`, `pattern`, `min-length`, `max-length`, `min`, `max` and
`step` all feed native constraint validation, and `setCustomValidity()` covers
server-side errors.

## Accessibility

- `label` provides the accessible name — always set it. `aria-label` works too,
  but a visible label is better.
- Errors are announced through the supporting line; keep messages specific.
- `readonly` stays focusable and readable; `disabled` does not.
- The focus indicator is a 3px border by default
  (`--md-text-field-focus-border-width`), and `appear-focused` can force the
  focused look for composite triggers.
- The counter (`max-length`) is exposed alongside the field, not only visually.
- The clear, password-toggle and speech affordances are real buttons — each is
  reachable by keyboard, in DOM order after the input.
- `Escape` clears a `clearable="internal"` field and stops there, so an
  enclosing `<dialog>` does not also close.
- Verified against axe-core with zero WCAG 2.1 AA violations.

Tab through these: the read-only field takes focus and can be copied from, the
disabled one is skipped, the error field announces its message, and the last has
no visible label so it leans entirely on `aria-label`.

The last field has no visible `label`, so `aria-label` is the only accessible
name it has — prefer a visible label wherever the layout allows one. Note that
its clear button is its own tab stop, and that `Escape` clears the field without
leaving it.

:::note[Promoting the inner input to a combobox]
ARIA IDREFs don't cross the shadow boundary, so `aria-controls` /
`aria-activedescendant` added from outside can never resolve. The role and its
state are handed over as **props** instead: `input-role="combobox"`,
`input-expanded` and `input-aria-autocomplete` land on the real `<input>`, and
`aria-haspopup="dialog"` / `"listbox"` are mirrored from the host. A composite
that also needs the popup reference attaches it by element reflection —
`(await field.getInputElement()).ariaControlsElements = [listbox]` — which is
what [`md-autocomplete`](/components/autocomplete/) does.
:::

### Density and direction together

The `density` prop and a global `data-density` ancestor drive the same signal —
`--md-sys-density-scale` — so a wrapper sets the rung for everything inside it
and any one field can override it with a rung of its own.

:::caution[`density="0"` is not an opt-out]
Only the rungs `-1` through `-4` have a rule; there is no `:host([density="0"])`
and no `[data-density="0"]`. Because the signal is an inherited custom property,
a field written `density="0"` inside a `data-density="-2"` wrapper still
inherits `-2` and renders at 48px like its neighbours. To restore the default
rung on one element, reset the signal directly:
`style="--md-sys-density-scale: 0"`.
:::

**Density** — reach for a rung, not a hand-tuned height: the rung tapers the
container, the padding, the label and the glyphs together, which a `height`
override cannot. See [Density](/behaviour/density/).

**i18n** — translate `label`, `supporting-text`, `error-text`, `placeholder`,
`prefix-text` and `suffix-text`. Set `speech-lang` per locale, and use `Intl`
inside `formatter` for locale-correct numbers and currency.
