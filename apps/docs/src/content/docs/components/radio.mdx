**Exactly one option from a small, visible set.** Radios sharing a `name` form
an exclusive group with a roving tabstop and arrow-key navigation, and
participate in form submission and validation via `ElementInternals`.

:::danger[There is no default slot]
`<md-radio>Express</md-radio>` renders an empty circle — the text is dropped.
Wrap each radio in a `<label>`, or set `aria-label` / `aria-labelledby`. Same
contract as [`md-checkbox`](/components/checkbox/).
:::

## When to use

- **Five or fewer** mutually exclusive options that should all be visible.
- The user must make a deliberate, single choice before continuing.
- One option can be sensibly **pre-selected** — M3 expects this.

### When not to use

| Situation | Use instead |
|---|---|
| More than one option may be chosen | [`md-checkbox`](/components/checkbox/) |
| More than five options, or constrained space | [`md-select`](/components/select/) |
| A view/mode switch that stays visible | [`md-segmented-button`](/components/segmented-button/) |
| An immediate on/off setting | [`md-switch`](/components/switch/) |
| Filtering | [`md-chip`](/components/chip/) |
| Choosing from a long or remote list | [`md-select`](/components/select/) / [`md-autocomplete`](/components/autocomplete/) |
| Running an action | [`md-button`](/components/button/) |

### Decision cues

| Need | Setting |
|---|---|
| One choice from a visible set | This component |
| Group membership | A shared `name` |
| Preselect | `checked` on one member |
| Unavailable but discoverable | `soft-disabled` |
| Blocks submission when nothing is picked | `required` on a member |
| Smaller circles | `density="-1…-4"` |

## Grouping

**`name` is the group.** Grouping is by matching `name`, not by DOM nesting — a
`<fieldset>` alone does not scope anything. Two logically separate groups on one
page must use different names.

The group gets a **roving tabstop**: `Tab` enters the group once, arrow keys
move between options. That is the standard radiogroup pattern and it is
implemented for you.

## Forms & validation

`md-radio` is form-associated, so `name`/`value` submit without any hidden
`<input>`. Put `required` on the group's members and constraint validation
blocks submit until one is chosen, with `value-missing-label` as the message.

**Two ways to surface that message**, and the choice is yours:

- **Leave the form alone** and the *browser* reports it — the native bubble,
  positioned by the browser and styled by it, in its own timing.
- **Add `novalidate`** and render it yourself from `getValidity()`, as the demo
  below does. The message then lives on the **group**, which is where it belongs:
  a radio is one member of a set, so unlike [`md-checkbox`](/components/checkbox/)
  — a single control that owns its own `error-text` line — there is no one member
  for the message to hang off. The group markup is yours, so the message is too.

<ComponentDemo
  html={`<form data-pay novalidate style="display:flex; flex-direction:column; gap:12px; align-items:flex-start;">
  <div role="radiogroup" aria-labelledby="pay-label" aria-describedby="pay-error" style="display:flex; flex-direction:column; gap:8px;">
    <span id="pay-label" style="font-weight:600;">Payment method</span>
    <label style="display:flex; align-items:center; gap:8px;"><md-radio name="pay" value="card" required value-missing-label="Please choose a payment method."></md-radio> Card</label>
    <label style="display:flex; align-items:center; gap:8px;"><md-radio name="pay" value="bank" required value-missing-label="Please choose a payment method."></md-radio> Bank transfer</label>
    <span id="pay-error" data-pay-error role="alert" style="min-block-size:1.25em; color:var(--md-sys-color-error); font:400 12px/1.25em Roboto,system-ui,sans-serif;"></span>
  </div>
  <md-button variant="filled" type="submit">Pay</md-button>
  <output data-pay-out style="font:12px/1.6 ui-monospace,SFMono-Regular,Menlo,monospace; opacity:.85;"></output>
</form>`}
  script={`
  var form = root.querySelector('[data-pay]');
  var error = root.querySelector('[data-pay-error]');
  var out = root.querySelector('[data-pay-out]');
  var radios = root.querySelectorAll('md-radio[name="pay"]');

  form.addEventListener('submit', function (e) {
    e.preventDefault();
    radios[0].getValidity().then(function (v) {
      error.textContent = v.valid ? '' : v.validationMessage;
      out.textContent = v.valid
        ? 'FormData pay = ' + new FormData(form).get('pay')
        : '';
    });
  });

  radios.forEach(function (r) {
    r.addEventListener('mdChange', function () { error.textContent = ''; });
  });`}
  htmlForCode={`<form id="checkout" novalidate>
  <div role="radiogroup" aria-labelledby="pay-label" aria-describedby="pay-error">
    <span id="pay-label">Payment method</span>
    <label>
      <md-radio name="pay" value="card" required
                value-missing-label="Please choose a payment method."></md-radio>
      Card
    </label>
    <label>
      <md-radio name="pay" value="bank" required
                value-missing-label="Please choose a payment method."></md-radio>
      Bank transfer
    </label>
    <span id="pay-error" role="alert"></span>
  </div>

  <md-button variant="filled" type="submit">Pay</md-button>
</form>

<script type="module">
  const form = document.getElementById('checkout');
  const error = document.getElementById('pay-error');
  const radios = document.querySelectorAll('md-radio[name="pay"]');

  // novalidate suppresses the browser bubble; the group owns the message.
  form.addEventListener('submit', async (e) => {
    e.preventDefault();
    const { valid, validationMessage } = await radios[0].getValidity();
    error.textContent = valid ? '' : validationMessage;
    if (valid) save(new FormData(form).get('pay'));   // 'card' | 'bank'
  });

  radios.forEach((r) =>
    r.addEventListener('mdChange', () => { error.textContent = ''; }),
  );
</script>`}
  label="Required group — press Pay with nothing chosen"
  storyId="selection-radio--required"

## Events

| Event | Cancelable | Detail | Fires |
|---|---|---|---|
| `mdChange` | no | `{ checked, value }` | The radio becomes checked |
| `mdFocus` / `mdBlur` | no | `void` | Focus enters / leaves the control |
| `mdValidityChange` | no | `{ valid, validationMessage, flags }` | Validity is recomputed |

:::caution[`mdValidityChange` is not composed]
Listen on the element itself. A delegated listener on a shadow ancestor will
never see it.
:::

## Programmatic selection

`select()` checks this radio, unchecks its siblings, and emits `mdChange` as if
a user had done it.

<ComponentDemo
  html={`<div data-sel role="radiogroup" aria-label="Shipping" style="display:flex; flex-direction:column; gap:8px; align-items:flex-start;">
  <label style="display:flex; align-items:center; gap:8px;"><md-radio name="ship" value="std"></md-radio> Standard</label>
  <label style="display:flex; align-items:center; gap:8px;"><md-radio name="ship" value="exp"></md-radio> Express</label>
  <md-button data-sel-btn variant="outlined">Select Express from JS</md-button>
  <output data-sel-out style="font:12px/1.6 ui-monospace,SFMono-Regular,Menlo,monospace; opacity:.85;">mdChange has not fired yet</output>
</div>`}
  script={`
  var scope = root.querySelector('[data-sel]');
  var out = root.querySelector('[data-sel-out]');
  scope.querySelectorAll('md-radio').forEach(function (r) {
    r.addEventListener('mdChange', function (e) {
      out.textContent = 'mdChange → ' + JSON.stringify(e.detail);
    });
  });
  root.querySelector('[data-sel-btn]').addEventListener('click', function () {
    scope.querySelector('md-radio[value="exp"]').select();
  });`}
  htmlForCode={`<div role="radiogroup" aria-label="Shipping">
  <label><md-radio name="ship" value="std"></md-radio> Standard</label>
  <label><md-radio name="ship" value="exp"></md-radio> Express</label>
</div>

<script type="module">
  const express = document.querySelector('md-radio[value="exp"]');

  // Checks it, unchecks its siblings, and emits mdChange as a user click would.
  express.select();
</script>`}
  label="select() from JS — the group updates and mdChange fires, exactly as on a click"
  storyId="selection-radio--programmatic-control"
/>

`syncValidityFromGroup()` exists so siblings can agree on validity — it is a
coordination hook between radios, not something you normally call.

## Accessibility

- Wrap each radio in a `<label>` for its accessible name **and** a bigger hit
  target. There is no default slot, so unwrapped text is dropped.
- Name the **group** with `role="radiogroup"` + `aria-labelledby`, or a
  `<fieldset>`/`<legend>`. The component cannot do this for you.
- Roving tabstop: one `Tab` stop per group, arrows to move — implemented for
  you.
- `disabled` leaves the tab order; `soft-disabled` stays focusable so an
  unavailable option is still discoverable.
- Selection is conveyed by the inner circle, not by color alone.

### Keyboard

| Key | Action |
|---|---|
| `Tab` | One stop per group — it lands on the checked radio, or the first enabled one |
| `↑` / `←` | Previous option, wrapping (mirrored under `dir="rtl"`) |
| `↓` / `→` | Next option, wrapping |
| `Space` | Select the focused option |

Arrow keys **select as they move**, which is the ARIA radiogroup pattern —
there is no "preview without committing".

`value-missing-label` validation message.
