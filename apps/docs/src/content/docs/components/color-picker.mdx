**Pick an arbitrary colour.** A saturation/value plate with a hue slider,
optional alpha slider, numeric fields in hex / RGB / HSL, and an optional row of
preset swatches. Renders inline (default) or as a popover behind **your own**
trigger.

<ComponentDemo
  html={`<md-color-picker
  value="#6750A4"
  presets="#6750A4,#B3261E,#146C2E,#1B5E9F"
  aria-label="Accent colour"
></md-color-picker>`}
  label="Live preview"
  storyId="selection-color-picker--playground"
/>

:::note[Not a Material Design 3 component]
M3 has no colour-picker page. The Do & Don't below are **house rules** derived
from this component's behaviour and general form-control practice, not from
`m3.material.io`.
:::

:::danger[Not form-associated — you must submit the value yourself]
`md-color-picker` does **not** participate in `FormData`. A `name` attribute
does nothing. Listen for `mdChange` and mirror the value into a hidden input (or
your own state) — see [Forms](#forms).
:::

## When to use

- The user genuinely needs **arbitrary colour** selection: theming, drawing,
  labels, calendars, design tools.
- A brand or accent colour in a settings screen.

### When not to use

| Situation | Use instead |
|---|---|
| A small fixed palette (e.g. 8 label colours) | [`md-chip`](/components/chip/) or [`md-segmented-button`](/components/segmented-button/) swatches, or `presets` only |
| Choosing a semantic status | [`md-select`](/components/select/) with named options |
| A value that must submit with a form | Mirror it into a hidden field yourself |
| A greyscale / intensity amount | [`md-slider`](/components/slider/) |
| Only a hex string typed by hand | [`md-text-field`](/components/text-field/) with a pattern |

### Decision cues

| Need | Setting |
|---|---|
| Always-visible panel | `variant="inline"` |
| A trigger of your own that opens a dialog | `variant="popover"` + a slotted `trigger` |
| Transparency | An alpha-carrying `format`, plus the alpha track |
| A fixed palette to pick from | `presets` |
| Hide the numeric fields | `show-inputs="false"` — think first |
| Hide just the hex field | `show-hex="false"` |
| Compact panel | `density="-1…-4"` |

## Variants

| Variant | Behaviour |
|---|---|
| `inline` | **Default.** The panel is always visible — embed it in a settings panel or sidebar |
| `popover` | Opens the panel in a floating dialog behind a trigger **you** slot |

:::danger[`variant="popover"` has no trigger of its own]
There is deliberately **no built-in trigger** — a default would impose a
variant, a size and a label on every consumer. Slot your own into `trigger` and
the component wires activation plus `aria-haspopup="dialog"` and
`aria-expanded` onto it.

Any element works: an [`md-button`](/components/button/) of whatever variant and
size, an [`md-icon-button`](/components/icon-button/), or your own swatch. Omit
it and the popover has nothing to open it — the component warns in dev.
:::

For `variant="popover"`, `open` reflects the panel state and `show()` /
`close()` control it programmatically. `mdOpenChange` reports every transition.

:::caution[`dismiss-on-outside-click` is **off** by default]
This is the opposite of [`md-search`](/components/search/). Out of the box a
popover **stays open** until the trigger is clicked again, `close()` is called,
or `open` is set to `false` — clicking elsewhere on the page will not dismiss
it. Opt in explicitly, or provide your own close affordance.
:::

## Value & format

`value` is a **string in the current `format`**, and it is two-way bindable
(mutable + reflected).

| `format` | Emitted shape | With `alpha` |
|---|---|---|
| `hex` | **Default.** `#6750A4` | 8-digit hex, `#6750A4CC` |
| `rgb` | `rgb(103, 80, 164)` | `rgba(103, 80, 164, 0.8)` |
| `hsl` | `hsl(258, 34%, 48%)` | `hsla(258, 34%, 48%, 0.8)` |

On input, `value` accepts any 3/4/6/8-digit hex, `rgb()` or `rgba()` — but what
comes **out** always follows `format`.

:::danger[Changing `format` changes the shape of the string]
Pick one `format` and keep it stable. A consumer that parses `value` as hex will
break the moment `format` flips to `rgb` or `hsl` — the property, the attribute
and the `mdChange` detail all switch shape together.
:::

<ComponentDemo
  html={`<div style="display: flex; gap: 24px; flex-wrap: wrap;">
  <md-color-picker format="hex" value="#6750A4" show-inputs="false" aria-label="Hex output"></md-color-picker>
  <md-color-picker format="rgb" alpha value="rgba(103,80,164,0.8)" aria-label="RGBA output"></md-color-picker>

`alpha` only has meaning in formats that carry it — with `format="hex"` expect
the 8-digit form.

## Presets

`presets` accepts **either form** — the comma-separated attribute in markup, or
an array assigned as a property from JS. Whitespace and empty entries are
ignored either way, so it behaves like every other list-valued prop in the
library.

Presets render as a `role="listbox"` of focusable swatches below the sliders,
and clicking one commits immediately (it fires `mdInput` **and** `mdChange`).

:::caution[`show-inputs="false"` removes the exact-entry path]
The numeric fields are how a keyboard user enters a precise colour. Think hard
before switching them off — and never switch off both `show-hex` and
`show-inputs` unless the exact value is genuinely irrelevant.
:::

## Events

| Event | Cancelable | Detail | Fires |
|---|---|---|---|
| `mdInput` | no | `{ value: string }` | **Continuously** while dragging the plate, hue or alpha, and on every keystroke in a field |
| `mdChange` | no | `{ value: string }` | On commit — pointer release, field blur, `Enter`, or a preset click |
| `mdOpenChange` | no | `{ open: boolean }` | The popover opened or closed |

:::tip[Preview on `mdInput`, persist on `mdChange`]
`mdInput` fires once per pointer move — a single drag across the plate emits
dozens of events. Use it for live preview only; save, POST or push to history
on `mdChange`.
:::

## Testing

The plate, the hue slider and the alpha slider are **three separate drag
surfaces**. Each needs a real pointer drag — `pointerdown` → `pointermove` →
`pointerup` on that surface. A synthetic `click` will not move any of them, and
a drag on the plate says nothing about hue or alpha, so cover all three.

Setting `value` directly is the fast path for everything that is not
specifically about dragging.

## Accessibility

- Set `aria-label` — the default is the English string `"Color picker"`.
- **Always surface the value as text, not just a swatch.** The hex / RGB fields
  do this for you; a swatch alone conveys nothing to a colour-blind or
  screen-reader user. This is the single most common accessibility defect here.
- The numeric fields are the keyboard-accessible route to an exact colour —
  `show-inputs="false"` removes it, so think hard before setting it.
- The plate is `role="application"` with arrow-key handling; the hue and alpha
  tracks are `role="slider"` with `aria-valuenow`. All three are in the tab
  order unless `disabled`.
- Presets are focusable swatches inside a `role="listbox"`; give them meaningful
  surrounding text where you can.
- If the picked colour becomes UI foreground or background, **validate contrast
  yourself** — the component does not.
- The popover panel is a `role="dialog"` labelled by `aria-label`. The component
  puts `aria-haspopup="dialog"` and a live `aria-expanded` on **your** slotted
  trigger — but its accessible **name** is yours to write, since the element is
  yours (an icon-only trigger needs an `aria-label`).

### Keyboard

| Key | Action |
|---|---|
| `Tab` | Plate → hue track → alpha track → numeric fields → presets |
| `←` `→` `↑` `↓` | Move the plate thumb, or step the focused hue / alpha track |
| `Home` / `End` | Jump a track to its ends |
| `Enter` / `Space` | Pick a focused preset; open the popover from its trigger |
| `Escape` | Close the popover, returning focus to the trigger |
