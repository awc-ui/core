**A set of related buttons that behave as one control.** It wraps
[`md-button`](/components/button/) / [`md-icon-button`](/components/icon-button/)
children, forces them into toggle mode, and owns selection, roving tabindex,
arrow-key navigation and — in `connected` mode — the fused container shape.

## When to use

- 2–5 **related** actions or states that read as one unit: text alignment,
  zoom in/out/reset, view mode.
- You want **arrow-key navigation** and a single tab stop for the cluster.
- The buttons should visually respond to one another (`connected`).

### When not to use

| Situation | Use instead |
|---|---|
| Choosing between 2–5 exclusive **view/mode** options with labels | [`md-segmented-button`](/components/segmented-button/) |
| A default action plus variations of it | [`md-split-button`](/components/split-button/) |
| Unrelated actions that happen to sit near each other | Separate [`md-button`](/components/button/)s |
| Form field selection bound to a `<form>` | [`md-radio`](/components/radio/) / [`md-checkbox`](/components/checkbox/) |
| Many options, or options that need a menu | [`md-menu`](/components/menu/), [`md-select`](/components/select/) |
| Navigating between destinations | [`md-tabs`](/components/tabs/), [`md-navigation-bar`](/components/navigation-bar/) |
| A single action | [`md-button`](/components/button/) |

## The group takes over its children

This is the part that surprises people.

- It sets `toggle = true` on every child — you never set it yourself.
- It owns `connectedLeft`, `connectedRight`, `groupTabindex` and `value`
  positioning. Setting those by hand breaks the roving tabindex and the border
  trimming.
- **Every child needs a `value`.** It is the identity carried in `values`,
  `added` and `removed`.
- Children **self-toggle on click first**, then the group reconciles. In
  `single-select` it deselects the others; with `required` it re-selects the
  clicked button if the click would have emptied the selection.
- Only `md-button` and `md-icon-button` children are discovered. Anything else
  is ignored.

has one.

## Selection modes

`single-select` (the default) behaves like a radio group — role `radiogroup`,
one selection at a time. `multi-select` allows several at once and uses role
`group`.

`required` prevents the selection from ever emptying — the right choice for a

:::note[There is no initial event]
`mdSelectionChange` fires **only on user activation**. Set the starting state
with `selected` on the children, as above.
:::

survive; see [Group-owned child props](#api-reference).

## Events

| Event | Cancelable | Detail | Fires |
|---|---|---|---|
| `mdSelectionChange` | no | `MdButtonGroupChangeDetail` | Every user activation that lands on a discovered child |

The group does **not** compare the new selection with the old one before
emitting. Re-pressing the already-selected child of a `required`
`single-select` group still fires, with `added: []` and `removed: []` — guard
on the diff, not on the event, if a no-op should be ignored.

```ts
interface MdButtonGroupChangeDetail {
  values: string[];        // full selection snapshot AFTER the change
  added: string[];         // newly selected (usually 0–1)
  removed: string[];       // newly deselected (usually 0–1)
  originalEvent: MouseEvent;
}
```

:::tip[`values` is the snapshot, not the diff]
The most common mix-up on this component. `values` is the whole selection after
the change; the diff is `added` / `removed`.
:::

The event **bubbles** and is **composed**. Listen on the group — not on each
child's `mdClick`, which fires before the group reconciles.

there for the cases where the transition matters, such as animating the button
that just turned off.

### One click, three events

The group puts its children in toggle mode, so a single press produces a
cascade. All three `bubble` and are `composed`, so a listener on the **group**
receives every one of them — which is what you see in Storybook's Actions panel:

| Order | Event | Target | Detail |
|---|---|---|---|
| 1 | `mdClick` | the child | `{ value, toggle, selected, href, target, originalEvent }` |
| 2 | `mdChange` | the child | `{ selected, value }` |
| 3 | `mdSelectionChange` | **the group** | `{ values, added, removed, originalEvent }` |

:::note[`md-icon-button` children are quieter]
The table above describes `md-button` children. An `md-icon-button` child emits
`mdClick` with a `{ selected }` detail only, **no `mdChange` at all**, and its
`mdClick` is **not cancelable** — it toggles itself and emits without ever
checking `defaultPrevented`, so there is nothing to veto. A group of icon
buttons therefore produces two events per press, not three, and neither of them
is a before-change hook. The group's `mdSelectionChange` is identical whatever
the children are, which is one more reason to listen there.
:::

:::danger[Child events miss deselections]
Switching from `a` to `b` in `single-select` fires **three** events, not four.
`mdChange` fires only for the button you *pressed* (`b`, `selected: true`). The
button that was turned off emits **nothing** — the group clears it
programmatically, and `md-button` has no watcher on `selected`, so there is no
event to emit.

Only `mdSelectionChange` reports the full picture:
`values: ['b'], added: ['b'], removed: ['a']`.

So **listen on the group, not the children.** Wiring `mdChange` per child looks
like it works — every press fires one — while silently dropping every
deselection.
:::

Listen to the child events only when you genuinely care about the press itself.
On an **`md-button`** child `mdClick` is cancelable, so that is where you veto
an activation before the group reconciles. On an **`md-icon-button`** child it
is not — the group below is icon-only, so nothing here can be vetoed; it just
reads the group's own selection.

:::note[Inherited child events]
`mdSelectionChange` is the only event this component **declares**, but a
listener on the group also receives the children's own
[`mdClick`](/components/button/#events) and
[`mdChange`](/components/button/#events), because both bubble and are composed.
Which of those you get depends on the child: `md-button` emits both, and its
`mdClick` is cancelable — that is the one place to veto an activation before the
group reconciles. `md-icon-button` emits only `mdClick`, **not cancelable**, so
an icon-only group has no veto hook at all. `mdChange` misses deselections
inside a group either way; see
[One click, three events](#one-click-three-events).
:::

:::caution[Group-owned child props]
The group sets `toggle`, `shape`, `size`, `connectedLeft` and `connectedRight`
on every child, and owns their `groupTabindex`. Setting those by hand breaks the
roving tabindex and the connected border trimming.
:::

## Accessibility

- Role is `radiogroup` in `single-select` and `group` in `multi-select`.
  Children expose `aria-pressed` through their own toggle mode.
- **One tab stop** for the whole cluster (roving tabindex). In `single-select`
  the selected child is the tab stop.
- `ArrowLeft` / `ArrowRight` move focus, `Home` / `End` jump to the ends.
- Give the group itself an `aria-label` describing what it controls
  ("Text alignment"), and every icon-only child its own `aria-label`.
- `required` prevents an empty selection, which keeps the `radiogroup`
  semantics honest.

Both rows above are **one tab stop each**. Tab moves you into the group and
straight out again; `ArrowLeft` / `ArrowRight` move within it and `Home` / `End`
jump to the ends — the composite-widget pattern, not three separate stops.

The role changes with the mode: `single-select` is a `radiogroup`, `multi-select`
is a plain `group`. Every child here is icon-only, so each carries its own
`aria-label`, and the group carries one describing what it controls.

:::caution[Two names, both required]
The group's `aria-label` names the *cluster* ("Text alignment"); each child's
names the *option* ("Align left"). Omit the group's and a screen-reader user
hears three unrelated toggles; omit a child's and they hear an unnamed button.
:::

:::caution[Keep the hit area honest]
Density is not what puts these groups under the 48×48 comfortable touch
target — the default `size` already does. Every demo above uses `sm` children,
which are **40px** tall at rung `0`; each rung then trims another 4px, so `-1`
is 36px, `-2` is 32px, `-3` is 28px and `-4` hits the 24px floor. (`xs`
children start at 32px and get smaller still.)

If the group has to be touch-friendly, raise `size` — `md` children are 56px —
rather than assuming rung `0` is safe. Reserve the low rungs for pointer-first,
information-dense screens. See [Density](/behaviour/density/#accessibility).
:::

## Theming

| Custom property | Purpose | Default |
|---|---|---|
| `--md-button-group-gap` | Spacing between children | `standard`, per size: 18px (`xs`), 12px (`sm` — the default), 8px (`md`/`lg`/`xl`), each tapering to roughly half across the density range. `connected`: a fixed 2px seam that does **not** taper |
| `--md-button-group-width` / `-min-width` / `-max-width` | Inline-size bounds | `auto` / `auto` / `none` |
| `--md-button-group-height` / `-min-height` / `-max-height` | Block-size bounds | `auto` / `auto` / `none` |

:::tip[Theme the children, size the group]
There is no `--md-button-group-container-color`. The group's own custom
properties are all **geometry** — `gap`, `width` / `min-width` / `max-width`,
`height` / `min-height` / `max-height`. Colour a group by targeting its
`md-button` children, as above.
:::

:::danger[`md-button[selected]` does not track the selection]
Two traps, and the demo above sidesteps both.

**Match the class, not the attribute.** `selected` on `md-button` is a plain
mutable prop with **no `reflect`**, so the `selected` *attribute* stays on
whichever child you authored it on and never moves. Selection is exposed on the
host as the class `.md-button--selected`, which does move — target that.

**Colour both branches, or neither.** `md-button` reads
`var(--md-button-container-color, …)` in *every* toggle branch, so a value set
on the bare child wins in the selected and unselected state alike and erases
the component's own differentiation. Either scope each colour to a branch
(`:not(.md-button--selected)` / `.md-button--selected`, as above), or set only
the selected branch and let the component keep its default for the rest.
:::

```css
/* Geometry on the group, colour on the children. */
.toolbar-range {
  --md-button-group-gap: 2px;
  --md-button-group-max-width: 420px;
}

/* The host class tracks the selection; the `selected` attribute does not. */
.toolbar-range md-button.md-button--selected {
  --md-button-container-color: var(--md-sys-color-secondary-container);
  --md-button-label-color: var(--md-sys-color-on-secondary-container);
}
```
