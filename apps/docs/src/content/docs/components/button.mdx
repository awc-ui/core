## When to use

- A **discrete action** the user commits to: `Save`, `Confirm`, `Join now`.
- Actions inside dialogs, forms, cards, toolbars and bottom sheets.
- A **binary toggle with a visible label** — Save / Favorite / Follow.
- A submit or reset control inside a `<form>`.

### When not to use

| Situation | Use instead |
|---|---|
| Icon-only affordance, no label | [`md-icon-button`](/components/icon-button/) |
| Navigating between app destinations | [`md-navigation-bar`](/components/navigation-bar/), [`md-navigation-rail`](/components/navigation-rail/), or a text link |
| The single most prominent action (mobile) | [`md-fab`](/components/fab/) |
| 3+ related actions acting as one unit | [`md-button-group`](/components/button-group/) |
| One primary action plus variations of it | [`md-split-button`](/components/split-button/) |
| Filtering, attributes, removable entries | [`md-chip`](/components/chip/) |
| Low-priority actions crowding the UI | Overflow [`md-menu`](/components/menu/) |

## Variants

Pick by emphasis, highest first. M3: use the strongest style **sparingly** —
ideally one `filled` button per screen.

| Variant | Emphasis | Use for |
|---|---|---|
| `filled` | Highest | The one flow-completing action |
| `tonal` | High-ish | Lower priority, more weight than an outline |
| `elevated` | Medium | Needs separation from a busy background |
| `outlined` | Medium | Important, but not primary |
| `text` | Lowest | Several options side by side; dialogs, cards |

## Shape & shape morph

`shape` sets the **resting** geometry. `shape-morph` (default `true`) animates
the radius on press and on toggle — pressed buttons square off by one step;
`round` toggles morph to square when selected, and `square` toggles morph to
round.

## Icons

A leading icon is the M3 default. Icons come from the `icon` /
`trailing-icon` props, or the matching **named slots** for custom glyphs
(SVG, icon font, emoji) — a slot replaces the corresponding prop.

<ComponentDemo
  html={`<md-button variant="filled" icon="add">Add item</md-button>
<md-button variant="outlined" trailing-icon="arrow_forward">Next</md-button>
<md-button variant="tonal">
  <svg slot="leading-icon" viewBox="0 0 24 24" width="18" height="18" fill="currentColor"><path d="M12 2l3.09 6.26L22 9.27l-5 4.87 1.18 6.88L12 17.77l-6.18 3.25L7 14.14 2 9.27l6.91-1.01L12 2z"/></svg>
  Starred
</md-button>`}
  label="Leading, trailing and custom icons"
/>

:::note[Two icons: the M3 tension]
M3 says a standard button carries at most **one** icon, yet both `icon` and
`trailing-icon` exist. The trailing slot is for *disclosure* affordances — a
chevron on a dropdown trigger — not a second meaning-bearing icon.
:::

## States

`disabled`, `soft-disabled` **and `loading`** all make the button inert —
`loading` is not merely cosmetic.

| State | Focusable | Use when |
|---|---|---|
| `disabled` | No (`tabindex="-1"`) | The action is unavailable and undiscoverable |
| `soft-disabled` | **Yes** | Contextually unavailable but worth discovering — M3's preference |
| `loading` | No | An async operation is in flight |

:::caution[It will not match the built-in spinner's size]
`md-progress-indicator` clamps its circular variant to M3's **24dp minimum**, so
it renders larger than the `loading` spinner (14px at `sm`) and suits size `md`

floor, so it can track the icon box down to 10px.

Keep `soft-disabled` on the button so the busy state still swallows activation;
the `loading` prop does that for you, a slotted spinner does not.
:::

## Links

Set `href` and the button navigates instead of acting.

```html
<md-button variant="text" href="/settings">Settings</md-button>
<md-button variant="text" href="https://example.com" target="_blank">External</md-button>
```

  html={`<md-button variant="filled" href="https://m3.material.io" target="_blank" trailing-icon="open_in_new">M3 guidelines</md-button>

:::danger[`href` wins over `type`]
If `href` is set the button navigates and **never** submits or resets a form.
Navigation goes through `window.open(sanitizeHref(href), target)`; unsafe
schemes such as `javascript:` are refused, and the form is *not* submitted as
a fallback.

## Events

| Event | Cancelable | Detail | Fires |
|---|---|---|---|
| `mdClick` | **yes** | `MdButtonClickDetail` | Every activation (pointer, `Enter`, `Space`) |
| `mdChange` | no | `{ selected, value }` | Only when `toggle` mode flips `selected` |

### Why two events and not one

`mdChange`'s payload is a strict subset of `mdClick`'s, so the difference is not
the data — it is the **guarantee**.

`mdClick.detail.selected` is a *prediction*: the state the button will take **if
nothing cancels the click**. A listener registered after yours can still call
`preventDefault()`, so a handler that commits on `mdClick` can commit a change
that never happened. `mdChange` fires after the flip and cannot be vetoed, so it
is the committed fact.

This is the same split the platform uses for `<input type="checkbox">` —
`click` is cancelable and predictive, `change` is settled — including the part
people forget: **neither fires on a programmatic change.** Setting
`btn.selected = true` in code emits nothing, exactly as `input.checked = true`
emits nothing. If your own code changes the state, your own code already knows.

| You want to… | Listen to |
|---|---|
| Veto the activation (guard, confirm, permission check) | `mdClick` + `preventDefault()` |
| React to a committed toggle | `mdChange` |
| Handle a plain, non-toggle button press | `mdClick` |
| Know the *previous* state | `mdClick` — `detail.selected` is the incoming one |

```ts
interface MdButtonClickDetail {
  value: string;
  toggle: boolean;
  selected: boolean;   // the state the button WILL take — a before-change hook
  href: string;
  target: string;
  originalEvent: MouseEvent | KeyboardEvent;
}
```

:::tip[`detail.selected` is the post-click state]
It describes what the button *will* become if the click is not cancelled, which
makes `mdClick` a clean "before-change" hook. `preventDefault()` vetoes the
toggle flip **and** the `href` navigation — the underlying DOM `click` still
bubbles.
:::

Both events **bubble** and are **composed**, so one delegated listener on an
ancestor catches every button.

## Accessibility

- The host **is** the button: `role="button"`, `Enter`/`Space` activation, and
  a 3px focus ring at 2px offset on every variant.
- `aria-disabled` is set whenever `disabled`, `soft-disabled` **or** `loading`
  is active.
- `aria-pressed` is emitted **only** in `toggle` mode.
- Add `aria-label` whenever the visible label is insufficient. Verified against
  axe-core with zero WCAG 2.1 AA violations.
- Prefer `soft-disabled` over `disabled` for contextually-unavailable actions —
  it stays focusable, so keyboard users can still discover it.
- `role-override` exists for composite widgets (e.g. `gridcell` in
  [`md-date-picker`](/components/date-picker/)). Leave it empty otherwise.

Tab through these: the soft-disabled button still takes focus, the disabled one
is skipped, and the toggle announces its pressed state.

  html={`<md-button variant="filled">Focusable</md-button>
<md-button variant="filled" soft-disabled>Soft-disabled — still focusable</md-button>
<md-button variant="filled" disabled>Disabled — skipped</md-button>
<md-button variant="tonal" toggle selected value="bookmark" icon="bookmark">Saved</md-button>

The last two show the two legitimate uses of `aria-label`. On the `md-button`
the visible word "Delete" is the label; `aria-label` **overrides** it with
something more specific for screen-reader users, who hear "Delete invoice 4021"
without the row context a sighted user gets for free. For a genuinely icon-only
control, reach for [`md-icon-button`](/components/icon-button/) — an
`md-button` with an icon and no text has no accessible name and the wrong
metrics, which is why it appears in [Anti-patterns](#anti-patterns) below.

## RTL, density & i18n

**RTL** — all box metrics use logical properties, so leading/trailing icons
swap automatically under `dir="rtl"`. Add `mirror-icon` for **directional**
glyphs only (`arrow_forward`, `chevron_right`, `send`); never for `add`,
`search` or `favorite`. See [RTL](/behaviour/rtl/).

```html
<div dir="rtl">
  <md-button variant="filled" trailing-icon="arrow_forward" mirror-icon>التالي</md-button>
</div>
```

**The same buttons in both directions.** Nothing is re-authored between them —
only `dir` changes. Box metrics are logical, so the icon moves to the trailing
edge on its own:

### Every density rung

the default the rungs taper away from.

:::caution[Below `-2`, check your touch targets]
The rungs shrink the hit area along with the row: 40px at `0` down to 24px at
`-4` for these buttons. That is well under the 48px pointer-coarse devices
want, and an icon-only button — with no label padding to help — is the first to
become hard to hit. See [Density](/behaviour/density/#accessibility) for the
media query that raises the target back on touch.
:::

### Density and direction together

The two are independent signals, so they compose without any extra wiring — here
a `dir="rtl"` container at `data-density="-2"`. The first three buttons inherit
that rung; the fourth tightens further with `density="-4"`; the last escapes the
inherited rung entirely by setting the signal itself.

<ComponentDemo
  html={`<div dir="rtl" data-density="-2" style="display:flex;gap:12px;flex-wrap:wrap;align-items:center;">
  <md-button variant="filled" icon="save">حفظ</md-button>
  <md-button variant="outlined" trailing-icon="arrow_forward" mirror-icon>التالي</md-button>
  <md-button variant="tonal" icon="search">بحث</md-button>
  <md-button variant="tonal" density="-4" icon="search">أضيق</md-button>
  <md-button variant="text" style="--md-sys-density-scale: 0;" icon="add">افتراضي</md-button>
</div>`}
  label="dir=rtl at data-density=-2, one button at -4, one escaping back to rung 0"
/>

:::caution[`density="0"` is not an opt-out]
No component defines a `[density="0"]` rule — the token layer leaves it out on
purpose, because reflected props write `density="0"` onto virtually every
element and such a rule would pin the whole library to rung 0 and break global
inheritance outright. Absence of a rung means "inherit whatever the ancestor
says", so `density="0"` inside a `data-density="-2"` subtree still renders at
`-2`. To reset a subtree, set `--md-sys-density-scale: 0` directly.
:::

**Density** — `density="-1…-4"` locally overrides the inherited `data-density`
rung. See [Density](/behaviour/density/).

**i18n** — the label is your slotted text, so it comes straight from your i18n
layer; `lang` and `dir` are inherited from any ancestor. Localize `aria-label`
too, and watch M3's length-stability rule on toggle labels.
