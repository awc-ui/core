**A temporary set of actions or options, anchored to a trigger.** It handles
placement, flipping, roving focus, typeahead and dismissal. It is also the
dropdown surface inside [`md-select`](/components/select/),
[`md-multi-select`](/components/multi-select/),
[`md-autocomplete`](/components/autocomplete/) and
[`md-date-picker`](/components/date-picker/).

The menus below start **closed** — click a trigger to open one.

<ComponentDemo
  html={`<md-icon-button id="menu-demo-more" icon="more_vert" aria-label="More actions" onclick="document.getElementById('menu-demo-overflow').show()"></md-icon-button>
<md-menu id="menu-demo-overflow" anchor="menu-demo-more" placement="bottom-start">
  <md-menu-item headline="Rename"></md-menu-item>
  <md-menu-item headline="Duplicate"></md-menu-item>
  <md-menu-item headline="Delete"></md-menu-item>
</md-menu>`}
  htmlForCode={`<md-icon-button id="more" icon="more_vert" aria-label="More actions"></md-icon-button>

<md-menu id="overflow" anchor="more" placement="bottom-start">
  <md-menu-item headline="Rename"></md-menu-item>
  <md-menu-item headline="Duplicate"></md-menu-item>
  <md-menu-item headline="Delete"></md-menu-item>
</md-menu>

<script type="module">
  const trigger = document.getElementById('more');
  const menu = document.getElementById('overflow');

  // The menu never wires its own trigger — opening it, and the trigger's ARIA,
  // are both yours.
  trigger.setAttribute('aria-haspopup', 'menu');
  trigger.addEventListener('click', () => menu.show());
  menu.addEventListener('mdOpen',  () => trigger.setAttribute('aria-expanded', 'true'));
  menu.addEventListener('mdClose', () => trigger.setAttribute('aria-expanded', 'false'));
</script>`}
  label="Live preview — click the trigger"
  storyId="navigation-menu--playground"
/>

## When to use

- A **temporary** set of actions from a trigger: overflow menus, context menus,
  row actions.
- More options than fit comfortably on screen — M3 notes a menu takes less
  space than a set of radio buttons or chips.
- Nested action groups via [`md-sub-menu-item`](/components/menu/#md-sub-menu-item).

### When not to use

| Situation | Use instead |
|---|---|
| Actions that should always be visible | [`md-toolbar`](/components/toolbar/) |
| Choosing a value in a form | [`md-select`](/components/select/) / [`md-multi-select`](/components/multi-select/) |
| 2–5 exclusive options | [`md-segmented-button`](/components/segmented-button/) |
| A list of records | [`md-list`](/components/list/) |
| A blocking decision | [`md-dialog`](/components/dialog/) |
| Supplementary panel content | [`md-side-sheet`](/components/side-sheet/) / [`md-bottom-sheet`](/components/bottom-sheet/) |
| Top-level navigation | [`md-navigation-bar`](/components/navigation-bar/) / [`md-navigation-rail`](/components/navigation-rail/) |
| One default action plus variants | [`md-split-button`](/components/split-button/) |

### Decision cues

| Need | Setting |
|---|---|
| Commands (rename, delete) | Default `menu` semantics |
| Values the user picks from | `listbox` + `presentation="option"` rows |
| Multi-select rows | `keep-open` on the items (add `persistent` only if the menu should also survive an outside click) |
| Sections with headings | `layout="grouped"` + `md-menu-item-group` |
| Surface at least as wide as the trigger | `match-anchor-width` |
| A sheet on compact viewports | `responsive` |
| No open animation | `quick` |

## Anchoring

:::caution[`anchor` is a global DOM `id`, resolved with `getElementById`]
The trigger stays **your** element — the menu only positions against it. An id
that lives inside another shadow root will not be found.
:::

The menu does **not** wire the trigger for you. Call `show()` yourself, and set
`aria-haspopup` / `aria-expanded` on the trigger — see
[Accessibility](#accessibility).

Any element can be the trigger — a button, an icon button, a chip, a row:

### Placement and auto-flipping

`placement` is logical, so `bottom-start` follows the reading direction. The
menu flips to the opposite side when it would overflow the viewport, and slides
along the anchor when it would run off the inline edge — you do not opt in.

*also* switch off outside-click dismissal, which a preference or sort menu
should keep:

  arbitrary layout changes:

  ```js
  window.addEventListener('resize', () => menu.open && menu.reposition());
  ```

  `setComboboxElement()` and `setVirtualProvider()` are integration hooks for

  ## The sub-components

  A menu is composed from three row types. They are documented here rather than
  on their own pages: none of them mean anything outside a menu, and the parent
  owns focus, keyboard navigation and dismissal for all of them.

  ### `md-menu-item`

  **One row in the menu** — a command, or a checkbox/radio option, with optional
  icons, supporting text, a badge and trailing text.

  :::danger[The item self-toggles before the parent reconciles]
  Clicking a `checkbox` / `radio` row flips `selected` on the item itself, then
  `mdClick` fires. A controlled parent that **rejects** the change — a
  `max-selected` cap, a failed save — must revert via `e.target`, or the user is
  left looking at a phantom check.

  ```js
  item.addEventListener('mdClick', (e) => {
    if (atCap()) e.target.selected = false;   // undo the optimistic toggle
  });
  ```
  :::

  - **Activating a row closes the menu** unless `keep-open` is set on the item or
    `persistent` on the menu. `keep-open` is the per-row opt-out; `persistent`
  is the whole-menu one and additionally disables outside-click dismissal, so
  reach for it only when you manage closing yourself.
  - **`type="radio"` does not group itself.** Put radio rows in an
    [`md-menu-item-group`](#md-menu-item-group) and enforce exclusivity in your
    handler — nothing does it for you.
  - `mdClick` carries **no payload**. Identify the row by the element you bound
    the listener to, or by its `headline`.
  - `indeterminate` is presentational only — a mixed state on a `checkbox` row.
    It is ignored for `button` / `radio` types and when `selected` is true.
  - `presentation` and `role-override` change the announced role. Leave them
    alone unless you are building a picker; `md-select` uses
    `presentation="option"` so its popup is a real listbox rather than a menu.
  - `density` here overrides the density inherited from the menu.

  <ApiTable {...menuItemApi} />

  ### `md-menu-item-group`

  **A labelled section within the menu** — groups related rows under a heading so
  a long menu stays scannable.

  :::caution[It groups; it does not manage selection]
  Radio rows inside a group are **not** made exclusive automatically. The group is
  visual and semantic grouping only — you enforce the one-of-many rule yourself:

  ```js
  for (const group of document.querySelectorAll('md-menu-item-group')) {
    const items = [...group.querySelectorAll('md-menu-item[type="radio"]')];
    items.forEach((i) =>
      i.addEventListener('mdClick', () => {
        items.forEach((o) => (o.selected = o === i));
      }),
    );
  }
  ```

  An unmanaged group can announce two selected radios at once, which is
  contradictory to assistive technology.
  :::

  - **An empty `label` defeats the point.** An unlabelled group adds nothing over
    flat rows — either provide a heading, or use `divider` on an item instead.
  - **Pair it with the menu's `layout="grouped"`.** Without it the spacing between
    sections doesn't render as intended.
  - Its only theming knob is `--md-menu-group-gap`, set on the menu — it exposes
    no custom properties, no events, no methods and no CSS parts of its own.
  - The default slot accepts [`md-menu-item`](#md-menu-item) and
    [`md-sub-menu-item`](#md-sub-menu-item) children.

  <ApiTable {...menuItemGroupApi} />

  ### `md-sub-menu-item`

  **A menu row that opens a nested submenu** — the same anatomy as
  [`md-menu-item`](#md-menu-item), plus a `submenu` slot holding the nested
  content.

  :::caution[Submenus are a web-only affordance]
  M3 notes that submenus do not translate to touch. **Never make a submenu the
  only route to an action** — provide a flat alternative on small screens, and
  keep nesting to **one** level. Three-level menu trees are unusable, especially
  with a keyboard.
  :::

  - **Nothing selectable here.** Unlike `md-menu-item` there is **no `type`, no
    `selected`, no `keep-open`** — a submenu row is a branch, not an option. If
    you are reaching for those, you want [`md-menu-item`](#md-menu-item).
  - **`collapse()` exists; there is no `expand()`.** Opening is driven by user
    interaction; `collapse()` closes the branch and resets its visual state, and
    an ancestor menu calls it on close so reopening always starts fresh.
  - `mdClick` fires for the **row itself** (not the submenu) and carries no
    payload.
  - The row exposes **no `--md-sub-menu-item-*` custom properties**. It inherits
    the `--md-menu-item-*` metrics from the menu.

  ## Accessibility

  - The menu manages roving focus, typeahead, `Escape` to close, and returns
    focus to the anchor.
  - **Wire the trigger yourself** with `aria-haspopup="menu"` (or `listbox` in
    `listbox` mode) and `aria-expanded`.
  - Provide `list-label` when the menu's purpose isn't obvious from the trigger.
  - A **closed** menu is `inert` and `aria-hidden` — don't fight that; it's what
    keeps hidden items out of the accessibility tree.
  - `auto-focus="false"` is for composites where focus must stay in a text field.
    In that case you must manage the announcements yourself, and note that ARIA
    IDREFs can't cross shadow boundaries.

  ### Keyboard

  | Key | Action |
  |---|---|
  | `↓` / `↑` | Move between enabled rows, wrapping at the ends |
  | `Home` / `End` | First / last row |
  | A–Z | Typeahead — jumps to the next row whose headline starts with the letters |
  | `Enter` / `Space` | Activate the row (closes unless `keep-open` / `persistent`) |
  | `→` | On a submenu row, open it and move into it (inverted under `dir="rtl"`) |
  | `←` | Close the submenu and return to its parent row |
  | `Escape` | Close, returning focus to the anchor |
  | `Tab` | Close and move on — a menu is not a tab stop |

## Theming

| Custom property | Purpose | Default |
|---|---|---|
| `--md-menu-min-width` / `--md-menu-max-width` | Surface width bounds | `112px` / viewport-clamped |
| `--md-menu-inline-surface-color` | Inline (embedded) surface tone | `transparent` |
| `--md-menu-inline-fill-radius-end` | Inline surface corner | `0` |
| `--md-menu-viewport-margin` | Gap from the viewport edge | — |
| `--md-menu-section-gap` | Space between groups | `2px` |
| `--md-menu-group-gap` | Space after a `md-menu-item-group` | `2px` |
| `--md-menu-item-height` | Row height (opts out of density) | 48px, density-derived |
| `--md-menu-item-padding-inline` | Row padding | `12px` |
| `--md-menu-item-gap` | Gap between row elements | `12px` |
| `--md-menu-item-icon-size` | Leading / trailing glyph | 24px (20px in `standard`/`vibrant`) |
| `--md-menu-item-check-size` | Selection check / radio glyph | `20px` |
