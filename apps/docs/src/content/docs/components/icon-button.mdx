A **common, recognisable action expressed as an icon alone** — close, delete,
share, more. Four emphasis styles, five sizes, three container widths, and an
optional toggle mode with a distinct selected glyph.

## When to use

- A **common action where the icon carries the meaning**: close, delete,
  share, edit, more.
- A control that **opens something else** — a menu, a search field, a sheet.
- A **binary toggle with no label**: favorite, bookmark, mute, pin.
- Dense containers — app bars, toolbars, cards, list rows, table cells — where
  a labelled button would not fit.

### When not to use

| Situation | Use instead |
|---|---|
| The action needs a text label to be understood | [`md-button`](/components/button/) |
| The single most prominent action on the screen | [`md-fab`](/components/fab/) |
| An action with **no** selected state, given `toggle` | Plain icon button — M3 warns against this |
| Filtering, attributes, removable entries | [`md-chip`](/components/chip/) |
| Choosing between 2–5 exclusive options | [`md-segmented-button`](/components/segmented-button/) |
| Navigating between destinations | [`md-navigation-bar`](/components/navigation-bar/) |

:::danger[`aria-label` is mandatory]
There is no visible text, so without `aria-label` the button has **no
accessible name**. This is by far the most common defect with this component.
:::

## Variants

Emphasis, highest first. M3: use `filled`, `tonal` or `outlined` when the
button needs **visual separation from its background**; `standard` has no
container until you interact with it.

| Variant | Emphasis | Use for |
|---|---|---|
| `filled` | Highest | Key actions — download, delete. Use sparingly |
| `tonal` | High-ish | A secondary action beside a high-emphasis one |
| `outlined` | Medium | Not the focus of the interaction |
| `standard` | Lowest | **Default.** Low emphasis, or on a colourful surface |

## Sizes & width

The default is **`sm`**, not `md`.

| Size | Height | Typical use |
|---|---|---|
| `xs` | 32px | Table rows, dense toolbars |
| `sm` | 40px | **Default.** App bars, cards, list rows |
| `md` | 56px | Touch-first surfaces |
| `lg` | 96px | Prominent standalone control |
| `xl` | 136px | Hero / media control |

`button-width` — `narrow`, `default`, `wide` — widens the container without
changing the glyph or the height.

## Toggle

`toggle` adds a selected state and emits `aria-pressed` automatically. Provide
`selected-icon` so the glyph changes too — M3 wants an **outlined** icon when
unselected and a **filled** one when selected.

<ComponentDemo
  html={`<md-icon-button toggle icon="favorite_border" selected-icon="favorite" aria-label="Add to favorites"></md-icon-button>
<md-icon-button toggle icon="bookmark_border" selected-icon="bookmark" variant="tonal" aria-label="Bookmark"></md-icon-button>
<md-icon-button toggle selected icon="star_border" selected-icon="star" variant="filled" aria-label="Star"></md-icon-button>`}
  label="Toggle buttons"
/>

:::caution[Without `selected-icon` only the container colour changes]
The same glyph then shows in both states. Provide the filled counterpart, or
the `selected` slot for a custom glyph.
:::

`disabled` leaves the tab order (`tabindex="-1"`); `soft-disabled` stays
focusable so the action remains discoverable. There is **no `loading` prop** —
that is [`md-button`](/components/button/) only.

## Events

| Event | Cancelable | Detail | Fires |
|---|---|---|---|
| `mdClick` | **no** | `{ selected: boolean }` | Every activation. In toggle mode `selected` is the **already-flipped** state |

:::caution[Not cancelable — unlike `md-button`]
The toggle has already flipped when `mdClick` fires. To reject a change, set
`selected` back in your handler.
:::

`detail.selected` is present on **every** `mdClick`, not just toggles — on a
plain icon button it is always `false`, so a shared handler can read it without
checking whether `toggle` is set.

## Accessibility

- **`aria-label` is required.** Localize it.
- `aria-pressed` is emitted automatically in toggle mode — don't set it yourself.
- If the button opens a popup, add `aria-haspopup` (and `aria-expanded` where
  you own the open state).
- Pair with [`md-tooltip`](/components/tooltip/) so the meaning is discoverable
  to sighted users — the tooltip is **not** the accessible name.
- Keep the touch target ≥48px: `size="xs"` plus a deep density rung can drop
  below it.

An icon button is **always** icon-only, so it always needs a name from you.
There is no visible label to fall back on:

**action**, not the current state: "Star this invoice", not "Starred". The
state is announced separately, and a name that flips with it gets read twice.

## RTL, density & i18n

**RTL** — the container is symmetric, so nothing flips automatically. If the
glyph is **directional** (`arrow_back`, `chevron_right`, `send`), swap the icon
name yourself. See [RTL](/behaviour/rtl/).

**Density** — `density="-1…-4"` shrinks the container; verify the hit target.
See [Density](/behaviour/density/).

**i18n** — `aria-label` and any tooltip text come from your dictionary; the
component renders no text of its own.

  </div>

  label="Placement flips with dir; the glyphs themselves do not"
/>

:::caution[There is no `mirror-icon` here]
Unlike [`md-button`](/components/button/#mirror-icon-is-per-glyph-not-per-button),
`md-icon-button` has **no `mirror-icon` prop**. The box metrics are logical, so
placement flips on its own, but a *directional glyph* will not.

Flip one yourself through `::part(icon)`, scoped to RTL so it only applies where
it should:

```css
[dir="rtl"] md-icon-button.is-directional::part(icon) {
  transform: scaleX(-1);
}
```

Only do it for glyphs that point — `arrow_forward`, `chevron_right`, `send`.
A magnifier or a heart points nowhere and mirroring it just looks wrong.
:::

:::caution[It floors at 32px, and 32px is still small]
The container is `max(32px, 40px + scale × 4px)`, so the rungs measure
**40 / 36 / 32 / 32 / 32px** — `-3` and `-4` are identical to `-2` because the
floor has already been hit. That floor is deliberate, but 32px is well under the
48px a pointer-coarse device wants, and an icon button has no label padding to
soften it. Raise the target back on touch — see
[Density](/behaviour/density/#accessibility).
:::
