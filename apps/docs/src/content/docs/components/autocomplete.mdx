## When to use

- A long or open-ended option set the user narrows **by typing**: cities,
  users, products, tags.
- Values that may not exist yet, where the user can enter their own
  (`free-solo`).
- Multi-value entry rendered as chips (`multiple`).

### When not to use

| Situation | Use instead |
|---|---|
| A short, closed list | [`md-select`](/components/select/) |
| Several values from a **known** closed list | [`md-multi-select`](/components/multi-select/) |
| App-wide search with a results surface | [`md-search`](/components/search/) |
| Plain text with no suggestions | [`md-text-field`](/components/text-field/) |
| 2–5 exclusive options | [`md-segmented-button`](/components/segmented-button/) / [`md-radio`](/components/radio/) |
| Assigning a subset from a pool | [`md-transfer-list`](/components/transfer-list/) |

## Supplying options

Three sources, and **slotted options win**:

1. Slotted [`md-select-option`](/components/select-option/) children — best for
   a static list you can write in markup.
2. The `options` **property** — an array of
   `{ value, label, supportingText?, icon?, iconColor?, disabled? }`, for data
   that comes from your state layer.
3. The `options` **attribute** — the same array as a JSON string, for a page
   that has its data up front and no reason to reach for a script.

:::note[Which form to use]
The attribute is parsed once, on the element. Prefer the **property** whenever
the data is dynamic — a framework binding re-runs on change, whereas rewriting a
JSON attribute means re-serialising the whole list. Malformed JSON degrades to an
empty list with a console warning rather than throwing.

`filterer` is a **function** and has no attribute form — assign it in JS.
:::

## `value` vs `inputValue`

The single most common mix-up on this component.

| | Holds | Reported by |
|---|---|---|
| `value` | The **committed selection** — a `string`, or `string[]` when `multiple` | `mdChange` |
| `inputValue` | The **raw text in the box** | `mdInput` |

Reading `value` to get what the user typed returns the last selection, not the
text. Reading `mdInput` as a selection fires on every keystroke.

## Multiple selection

`multiple` turns `value` into a `string[]` and renders each pick as a chip.
`chip-position` places the chip rail — `below` (default), `top`, `left`,
`right` or `inline`. A multi-select menu **already stays open** after a pick, so
several can be made in a row; `disable-close-on-select` is for **single** mode,
and it also makes the popup persistent — no outside-click dismissal, only
Escape, the trigger or a pick closes it.

It is not "nothing selectable". To block selection entirely use `disabled`.

`clear-on-blur` discards unmatched text when the field loses focus — **strict
single mode only**: it is ignored when `multiple` or `free-solo` is set, and it
never fires while the popup is open (arrowing into the listbox must not wipe the
active filter).

## Filtering

`filter-mode` picks a built-in matching strategy (`substring` by default).
`filterer` replaces matching entirely and is a **function property**:

<ComponentDemo
  html={`<div style="display:flex; flex-direction:column; gap:10px; align-items:flex-start;">
  <md-autocomplete data-filt label="Country (prefix match)" placeholder="Type “ge”…" style="inline-size: 300px;"></md-autocomplete>
  <output data-filt-out style="font:12px/1.6 ui-monospace,SFMono-Regular,Menlo,monospace; opacity:.85;">substring would match “Algeria” on “ge” — this prefix filterer does not.</output>
</div>`}
  script={`
  var el = root.querySelector('[data-filt]');
  var out = root.querySelector('[data-filt-out]');
  el.options = [
    { value: 'de', label: 'Germany' },
    { value: 'ge', label: 'Georgia' },
    { value: 'dz', label: 'Algeria' },
    { value: 'fr', label: 'France' },
  ];
  el.filterer = function (options, ctx) {
    var q = (ctx.inputValue || '').toLowerCase();
    var matches = options.filter(function (o) {
      return o.label.toLowerCase().indexOf(q) === 0;
    });
    out.textContent = 'filterer(' + JSON.stringify(ctx.inputValue) + ') → ' +
      JSON.stringify(matches.map(function (o) { return o.label; }));
    return matches;
  };`}
  htmlForCode={`<md-autocomplete id="country" label="Country"></md-autocomplete>

<script type="module">
  const el = document.getElementById('country');

  // Function property — there is no filterer attribute.
  el.filterer = (options, { inputValue }) =>
    options.filter((o) => o.label.toLowerCase().startsWith(inputValue.toLowerCase()));
</script>`}
  label="Type “ge” — the prefix filterer keeps Germany and Georgia, and drops Algeria"
  storyId="text-inputs-autocomplete--playground"
/>

`limit-results` caps how many suggestions **render** on the client-side path —
a rendering guard, not a search limit, since matching still scans every option.
The virtualized path ignores it: the WASM listbox windows its own rows.

## Large option sets

`virtualize="always"` renders rows on demand; pair it with `row-height` so the
scroller can size itself. `virtualize="auto"` (the default) decides for you.

For a dataset that big, **don't hand it an array** — `options` would mean
materialising every row on the JS heap. `loadOptions({ count, getRow })` takes a
row *factory* and packs the rows into the WASM store one at a time, so the data
never exists in JS. Filtering and scrolling then run against the packed store.

<ComponentDemo
  html={`<div style="display:flex; flex-direction:column; gap:10px; align-items:flex-start;">
  <div style="display:flex; gap:8px; flex-wrap:wrap; align-items:center;">
    <md-button data-load="100000" variant="filled">100k</md-button>
    <md-button data-load="1000000" variant="outlined">1M</md-button>
    <md-button data-load="10000000" variant="outlined">10M</md-button>
  </div>
  <md-autocomplete data-virt label="Option" virtualize="always" row-height="48" style="inline-size: 300px;"></md-autocomplete>
  <p data-virt-status style="font:500 12px/16px Roboto,system-ui,sans-serif; color:var(--md-sys-color-on-surface-variant); margin:0; min-block-size:16px;"></p>
</div>`}
  script={`
  var el = root.querySelector('[data-virt]');
  var status = root.querySelector('[data-virt-status]');
  var buttons = [].slice.call(root.querySelectorAll('md-button[data-load]'));
  var ticker;

  function load(count, btn) {
    if (ticker) return;                 // a pack is already running
    buttons.forEach(function (b) {
      b.variant = b === btn ? 'filled' : 'outlined';
      b.disabled = true;                // a second 10M pack queued behind the first looks hung
    });

    var t0 = performance.now();
    // Ten million rows take seconds. Count them off so the wait reads as work in
    // progress rather than a frozen page.
    var tick = function () {
      status.textContent =
        'Packing ' + count.toLocaleString() + ' rows… ' +
        ((performance.now() - t0) / 1000).toFixed(1) + 's';
    };
    tick();
    ticker = setInterval(tick, 100);

    // A row FACTORY, never an array: the WASM store pulls one row at a time, so
    // the dataset never exists on the JS heap. Keep the factory CHEAP — it runs
    // once per row, and toLocaleString() here cost 3.4s of the 10M pack.
    el.loadOptions({
      count: count,
      getRow: function (i) { return { value: 'v' + i, label: 'Option ' + i }; },
    }).then(function () {
      clearInterval(ticker);
      ticker = null;
      buttons.forEach(function (b) { b.disabled = false; });
      status.textContent =
        count.toLocaleString() + ' options packed in ' + Math.round(performance.now() - t0) +
        'ms — open it, scroll, and type to filter.';
    });
  }

  buttons.forEach(function (b) {
    b.addEventListener('mdClick', function () { load(Number(b.getAttribute('data-load')), b); });
  });

  load(100000, buttons[0]);`}
  htmlForCode={`<md-autocomplete
  id="options"
  label="Option"
  virtualize="always"
  row-height="48"
></md-autocomplete>

<script type="module">
  const el = document.getElementById('options');

  // A row FACTORY, not an array: loadOptions packs the dataset into the WASM
  // store one row at a time, so the rows never exist on the JS heap.
  // Keep the factory cheap — it runs once per row. Formatting each label with
  // toLocaleString() added 3.4s to a 10M pack in this very demo.
  await el.loadOptions({
    count: 10_000_000,

## Events

| Event | Cancelable | Detail | Fires |
|---|---|---|---|
| `mdInput` | no | `string` | Every change to the typed text |
| `mdChange` | no | `string \| string[]` | The committed selection changes |
| `mdOpen` / `mdClose` | no | `void` | The suggestion menu opens / closes |
| `mdClear` | no | `void` | The clear affordance is used |
| `mdValidityChange` | no | `{ valid, validationMessage, flags }` | Validity changes — **not composed** |

:::note[`mdValidityChange` does not cross shadow boundaries]
It is emitted with `composed: false`, so a listener on an ancestor **inside a
different shadow root** will never see it. `mdOpen` / `mdClose` are composed.
:::

## Accessibility

- `label` names the field. The suggestion count is announced through a live
  region driven by `status-template` — keep the `{count}` placeholder when you
  translate it.
- Arrow keys move through suggestions, `Enter` commits, `Escape` closes.
- Chips name their own remove control — `Remove {label}`. Note that name and
  the clear button's `"Clear value"` are hard-coded English; neither has a prop
  yet.
- `reserve-supporting-space` avoids layout jump when errors appear.

:::note[How the combobox crosses the shadow boundary]
The textbox lives inside [`md-text-field`](/components/text-field/)'s shadow
root; the listbox lives in this component's. That breaks the wiring in two
separate ways: an `aria-controls` **IDREF between the two can never resolve**,
and an ARIA attribute written on the `<md-text-field>` host lands on the host,
not on the `<input>` a screen reader is actually sitting on.

So each half is solved differently:

- **role, `aria-expanded`, `aria-autocomplete`** are handed over as props —
  `input-role="combobox"`, `input-expanded`, `input-aria-autocomplete` — and
  md-text-field renders them onto the real input. The two state props are
  emitted only alongside the role, where they are allowed attributes.
- **the listbox reference** uses **ARIA element reflection**
  (`input.ariaControlsElements = [listbox]`), which takes an element rather than
  an id, and accepts a target in an ancestor tree. It is set while the popup is
  open and cleared on close.

Verified in the accessibility tree (Chrome DevTools → Accessibility): the
combobox reports `expanded` and a real `controls` relation to the listbox.
Where reflection is unavailable, the control is still a combobox with a truthful
expanded state, and `↓` moves **real focus** onto an option — the APG variant
that needs no reference at all.
:::

:::caution[axe will report `aria-required-attr` while the popup is open]
Assigning the element reference leaves an empty `aria-controls=""` attribute
behind, and axe reads attributes rather than the accessibility tree — so it
reports the required attribute as missing. The relation is real; the checker
cannot see element references. Prefer the accessibility tree when auditing this
one.
:::

## RTL, density & i18n

**RTL** — field, chips, caret and menu mirror under `dir="rtl"`.
