**The M3 Expressive loading moment.** A morphing-shape indicator for
indeterminate waits — distinct from a progress indicator, which reports *how far
along* something is. Two variants, a five-rung density ladder, a themable
`shape` part, and a three-prop API on purpose.

## When to use

- An **indeterminate** wait where you cannot report progress: a refresh, a
  search, an initial fetch.
- Pull-to-refresh and similar whole-screen refresh moments.
- Inside pickers while options load — which is exactly how
  [`md-select`](/components/select/),
  [`md-multi-select`](/components/multi-select/),
  [`md-autocomplete`](/components/autocomplete/) and
  [`md-search`](/components/search/) use it internally.

### When not to use

| Situation | Use instead |
|---|---|
| You know how far along the operation is | [`md-progress-indicator`](/components/progress-indicator/) (determinate) |
| Content whose shape is known | [`md-skeleton`](/components/skeleton/) |
| A button working after a click | [`md-button`](/components/button/) with `loading` |
| An operation that will become determinate | [`md-progress-indicator`](/components/progress-indicator/) — M3 says don't transition *from* a loading indicator |
| A long background job not blocking the view | Linear [`md-progress-indicator`](/components/progress-indicator/) |

:::caution[Always indeterminate — there is no `value`]
That is the whole distinction from
[`md-progress-indicator`](/components/progress-indicator/). Three props, no
events, no methods, no slots. If you are reaching for more control, you want the
progress indicator instead.
:::

## Variants

`variant` is the only visual switch. `uncontained` (the default) paints the bare
morphing shape onto whatever surface it sits on; `contained` adds its own
container behind it and re-tones the shape to `on-primary-container` so it reads
against that backdrop.

| Variant | Use for |
|---|---|
| `uncontained` | **Default.** On an existing surface — a list, a card body, a picker |
| `contained` | Over content or imagery, where the shape needs its own backdrop |

## Size

There is no `size` prop — scale it with the two custom properties. The defaults
are a 48px box around a 38px shape, so set
`--md-loading-indicator-shape-size` alongside `--md-loading-indicator-size` to
keep that proportion.

| Custom property | Default | Scales |
|---|---|---|
| `--md-loading-indicator-size` | `48px` | The overall box — and the `contained` backdrop |
| `--md-loading-indicator-shape-size` | `38px` | The morphing shape inside it |

:::tip[Set only one and the proportion drifts]
Both properties have independent defaults, so overriding
`--md-loading-indicator-size` alone leaves a 38px shape inside a 32px box — it
overflows. Change them as a pair, or reach for `density` instead, which moves
both from one signal.
:::

## Resolving it

It has **no timeout** — it spins until you remove it. Always resolve it on
failure as well as on success. Press either button: the failing one removes the
indicator just as the succeeding one does, and shows an error in its place.

:::danger[An unresolved indicator is a hang, not a wait]
There is no timeout and no failure state. If the request rejects and nothing
removes the element, the screen keeps promising work that stopped — and
`aria-live="polite"` keeps the stale "Loading" text in the accessibility tree.
Remove it in `finally`, not in the success branch.
:::

## Accessibility

- The host carries `role="progressbar"` with `aria-live="polite"`, plus an
  internal `role="status"` element holding the same text — so the label is
  announced when the indicator appears.
- `label` is the accessible name and defaults to the English `"Loading"`. Make it
  specific — "Refreshing messages".
- Some assistive technologies can focus a progressbar programmatically, so the
  component ships a focus ring: 3px `secondary` at 2px offset, following the
  container shape.
- `prefers-reduced-motion` is **already handled** — the morph is replaced by a
  gentle opacity pulse on a circle. You do not need to write that CSS.
- Because it is indeterminate, screen-reader users get **no completion cue** from
  the component: announce the **result** yourself when loading ends.
- Keep it in view, per M3 — an off-screen indicator is invisible to everyone.

Tab into the first one below to see the focus ring; the last pair shows the
announce-the-result pattern — a live region you own, next to the indicator you
remove.

## RTL, density & i18n

**RTL** — the morph is radially symmetric and the component is a single
centred box, so there is nothing to flip. `dir` still matters for the text you
put *next to* it, which is where the mirroring actually happens. See
[RTL](/behaviour/rtl/).

```html
<div dir="rtl">
  <md-loading-indicator variant="contained" label="جارٍ التحميل"></md-loading-indicator>
</div>
```

### Every density rung

inside it **38 → 35 → 32 → 29 → 26px**, so the proportion holds at every rung.

:::caution[The size properties silently defeat the ladder]
The rung is the *fallback*: the box resolves to
`var(--md-loading-indicator-size, max(32px, calc(48px + <rung> * 4px)))`. Set
the public property and it replaces the whole calc, so `density` stops moving
that dimension — silently, because nothing errors. Set them only when you need a
size the ladder does not reach, and then stop expecting the rung to do anything.
See [Density](/behaviour/density/#accessibility).
:::

### Density and direction together

The two are independent signals, so they compose without any extra wiring — a
wrapper sets the rung for everything inside it, and any one indicator can take a
tighter rung of its own.

:::caution[`density="0"` is not an opt-out]
Only `-1` through `-4` have a rule — there is deliberately no
`:host([density="0"])` and no `[data-density="0"]`. Because
`--md-sys-density-scale` is an inherited custom property, an indicator written
`density="0"` inside a `data-density="-2"` wrapper still inherits `-2` and
renders at 40px like its neighbours. To restore the default rung on one element,
reset the signal directly: `style="--md-sys-density-scale: 0"`.
:::

  <md-loading-indicator density="-4" label="أكثر إحكاما"></md-loading-indicator>
  <md-loading-indicator label="افتراضي" style="--md-sys-density-scale: 0;"></md-loading-indicator>
</div>`}
  label="dir=rtl with data-density=-2: two inherit, one tightens to -4, one resets the signal to 0"
/>

**Density** — `density="-1…-4"` locally overrides the inherited `data-density`
rung; `0` is the default value, not an override. See
[Density](/behaviour/density/).

**i18n** — translate `label`. It is the accessible name, and the English
default ships silently if you forget.

## Theming

| Custom property | Purpose | Default |
|---|---|---|
| `--md-loading-indicator-color` | Shape colour | `primary`, or `on-primary-container` on `contained` |
| `--md-loading-indicator-size` | Overall box | `48px` (density-scaled) |
| `--md-loading-indicator-shape-size` | Inner morphing shape | `38px` (density-scaled) |
| `--md-loading-indicator-container-color` | `contained` backdrop | `primary-container` |
| `--md-loading-indicator-container-shape` | `contained` corner radius | `corner-full` |

Every one is a plain custom property, so a class, an inline `style`, or an
ancestor rule all work — there is no themable API beyond the cascade.

<ComponentDemo
  html={`<md-loading-indicator label="Tertiary toned" style="--md-loading-indicator-color: var(--md-sys-color-tertiary);"></md-loading-indicator>
<md-loading-indicator label="Error toned" style="--md-loading-indicator-color: var(--md-sys-color-error);"></md-loading-indicator>
<md-loading-indicator variant="contained" label="Brand contained" style="--md-loading-indicator-color: #ffffff; --md-loading-indicator-container-color: #6200ee;"></md-loading-indicator>
<md-loading-indicator variant="contained" label="Squared container" style="--md-loading-indicator-container-color: var(--md-sys-color-secondary-container); --md-loading-indicator-container-shape: 8px;"></md-loading-indicator>
<md-loading-indicator label="Inline override" style="--md-loading-indicator-color: coral;"></md-loading-indicator>`}
  label="Themed instances"
  storyId="communication-loading-indicator--custom-css"
/>

:::caution[On `contained`, override the pair or neither]
The shape colour does not follow the backdrop. Set
`--md-loading-indicator-container-color` alone and the shape stays on
`on-primary-container`, which was picked for the *default* container — against
your new one the pair can fall below 3:1. Check any override in both themes; the
[dark-theme story](/storybook/?path=/story/communication-loading-indicator--dark-theme)
is the counterpart to the demo above.
:::

**CSS part** — `shape`, the morphing element itself. Use it for what a colour
token cannot express: opacity, or a filter.

<ComponentDemo
  html={`<style>
  .low-opacity::part(shape) { opacity: 0.87; }
  .shadow-shape::part(shape) { filter: drop-shadow(0 2px 4px rgba(0, 0, 0, 0.3)); }
</style>
<md-loading-indicator class="low-opacity" label="Reduced opacity"></md-loading-indicator>
<md-loading-indicator class="shadow-shape" label="Drop shadow"></md-loading-indicator>`}
  label="::part(shape) overrides"
/>

```css
md-loading-indicator::part(shape) {
  opacity: 0.87;
  filter: drop-shadow(0 2px 4px rgb(0 0 0 / 0.3));
}
```

:::danger[Don't reach for `animation: none` on the part]
Every shape in the morph comes from a `clip-path` declared *inside* the
keyframes; the element's own rule declares none. Kill the animation and the
clipping stops applying altogether, so what is left is the unclipped block —
a plain square, not a resting shape. And you do not need it:
`prefers-reduced-motion` is
handled inside the component, which swaps the morph for a circle with a gentle
opacity pulse. Writing your own reduced-motion rule overrides that with
something worse.
:::
