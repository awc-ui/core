# Wealth Management Console — Svelte

The Svelte flavour of the AWC UI **wealth** showcase vertical: a single-page
application built with Vite and a hand-rolled client router. No SvelteKit, no
adapter, no server — the wealth vertical is SPA-only by design.

Mounted at `/showcase/wealth/svelte/`. Dev server: **:4340** (the credit-risk
Svelte build's :4330 + 10, so both verticals run at once).

## What renders

The same six screens as every sibling build, behind the same routes from
`@awc-ui/showcase-kit/wealth`:

| Route                | Screen                                       |
| -------------------- | -------------------------------------------- |
| `/`                  | Book overview                                |
| `/holdings/`         | Holdings                                     |
| `/households/<id>/`  | Household drill (guards its own unknown ids) |
| `/proposals/`        | Proposals                                    |
| `/trade/`            | Trade                                        |
| `/planning/`         | Planning                                     |

Routes, tables, i18n, selectors, status maps and `app.css` all come from
`@awc-ui/showcase-kit/wealth` — nothing shared is restated here. The React
build (`../react`) is the source of truth for wealth behaviour; the credit-risk
Svelte build (`../../credit-risk/svelte`) is the source of truth for this
build's structure and idioms.

## Where this differs from the credit-risk Svelte build

- **The chrome outlives navigation.** `AppFrame.svelte` (app bar + navigation
  rail + compact bar + dock) wraps the route outlet in `App.svelte` instead of
  a `Shell` rendered inside every screen — the rail's active indicator has to
  be the same DOM element across navigations to animate.
- **`@awc-ui/core/css/pre-upgrade.css`** is imported in `main.ts` (the React
  build added it; credit-risk predates it).
- **Skeleton system.** `components/Screen.svelte` shows a measured placeholder
  once per screen for 550ms (`?skeleton=hold` / `?skeleton=<ms>` to inspect),
  painted OVER the real content, which keeps its box and is revealed by a
  visibility flip. Shapes live in `src/lib/skeletons/`.
- **Unknown household ids** 404 inside `HouseholdScreen`, not in the route
  table — mirroring the React build.
- **Per-screen CSS** (`trade.css`, `planning.css`, `snackbar.css`) lives in
  `src/lib/screens/` and is imported from the owning screen's script block.

## Idioms (the two things Svelte needs for raw `md-*` tags)

- Object/function props (`series`, `nodes`, `items`, `valueFormatter`, …) go
  through the `objectProps` action in `src/lib/elements.ts`.
- Custom events are plain `on:mdSortChange={…}` — real `addEventListener`s.
  Capture-phase vetoes use the `on:click|capture` modifier (the compact
  navigation bar needs it).

## Commands

```sh
pnpm sync-runtime   # copy packages/core/dist/md3 → public/awc-runtime/
pnpm dev            # sync-runtime + vite, http://localhost:4340/showcase/wealth/svelte/
pnpm build          # sync-runtime + vite build + fan-out-routes (the SPA fallback)
pnpm serve          # dumb file server over dist/ at the real mount (no history fallback)
pnpm lint           # svelte-check
pnpm verify         # build first; puppeteer SPA-behaviour suite on :4349
```

`public/awc-runtime/` is generated by `sync-runtime` and never committed. The
build MUST end with `fan-out-routes.mjs` or every deep link 404s on the dumb
file servers the parity/a11y verifiers use — and on the docs host.
