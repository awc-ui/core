## Exception decisions

**E1 — Emoji glyph advance in the label (proposed in `md-badge.md`, Swift only) — ACCEPTED, extended to Android.** Source behaviour: the badge width is the label run plus 2 × 4 px padding. Chrome 152/153 on macOS measures the truncated value "😀😀" (fixture `value-33`) at 24 px, so the badge is 32 px. Platform/API: CoreText fallback to AppleColorEmoji in SwiftUI `Text` (macOS and iOS: badge 39 pt) and Android's system Noto Color Emoji in Compose `Text` (36.95 dp, `packages/native-android/audits/md-badge.md` L35). Technical reason: the OS emoji font and its advances (including CoreText tracking at small sizes) differ from Chrome's macOS rendering. Matching Chrome would mean distorting the system glyphs, and Chrome on Android uses the same Noto font as native Android. User impact: a badge whose value contains emoji is a few points wider; height, padding and physical anchoring are unchanged. Tested native equivalent: width = measured native glyph run + source padding (tolerance 0.02), with height, x/y anchor and label part checks (`NativeBadgeViewIntegration.swift` L111-122; Android `NativeBadgeParityTest` L130-150). Re-verified in r2-002/003/008 and r2-A001. Scope: glyph advances of emoji rendered by the OS emoji font only. Evidence: `outputs/native-parity/md-badge/swift-measurements-75.json`, `work/audit/r2/runs/swift/badge-measurements.json`.

**Extreme-input representable bounds (proposed as explicit boundaries in the platform audits) — ACCEPTED.** Source: absurd finite lengths (for example `1e308px`) saturate at Chrome's layout limit (16,777,214 units). Affected: Compose layout constraints (32,766 physical pixels, the Constraints encoding limit), SwiftUI/CoreGraphics allocation (bounded at the measured Chrome limit). Technical reason: a native layout cannot measure or allocate beyond its constraint encoding; the source itself saturates. User impact: none for representable sizes; the inputs involved are millions of pixels. Tested native equivalent: finite saturation with applied geometry reported by inspection (Android applied/clamped padding test in `NativeBadgeParityTest`). Scope: inputs beyond the platform's representable layout range only.
